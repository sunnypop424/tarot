# 보류 — 나중에 볼 것

리뷰(`docs/CODE_REVIEW_I18N.md`)와 작업 중에 나왔지만 **지금 고치지 않기로 한** 것들.
"안 한 것" 이 아니라 "지금 안 하는 게 낫다고 판단한 것" 이다 — 판단 근거를 같이 적는다.

각 항목은 **무엇을 · 왜 미뤘나 · 언제 다시 볼까**로 적는다.

---

## 1. 체험 슬롯 쓰기가 뚫려 있다 (이전부터 남아 있던 것)

- **무엇을:** RLS 정책이 OR 로 합쳐져서, `for all` 정책이 `manages_slot` 을 보는데
  `0034_demo_admin.sql` 이 체험 슬롯을 통과시킨다. 결과적으로 체험 슬롯은 아무나 쓴다.
- **왜 미뤘나:** 이번 작업(다국어·헤더 통일)과 축이 다르고, 체험 슬롯은 매시간 되돌아가
  실제 피해가 "남이 잠깐 바꿔 놓은 걸 다음 방문자가 본다" 로 한정된다.
  다만 **운영 슬롯 정책과 같은 파일을 만지므로** 손댈 때 한 번에 봐야 한다.
- **언제 다시 볼까:** 체험 슬롯을 홍보에 더 쓰기 전. 또는 RLS 를 다음에 만질 때 같이.

## 2. 토큰 사용량을 안 남긴다 (AI)

- **무엇을:** 호출 **횟수**는 `ai_usage` 에 쌓이는데(정산·한도의 근거), 응답의 `usage`
  (입력/출력 토큰)는 SSE 로 화면에 보내고 버린다.
- **왜 미뤘나:** **돈이 새는 자리가 아니다** — 예산 상한·레이트리밋·권한 게이트는 다 붙어 있다
  (`CLAUDE.md` §예산 방어). 없는 건 "원가 추정(`docs/PRICING.md`)을 실제와 맞춰볼 근거" 뿐이다.
- **언제 다시 볼까:** 가격을 다시 매길 때. 그전엔 추정치로 충분하다.

## 3. `myReward` 가 보상마다 설정 행을 한 번 더 읽는다

- **무엇을:** 선물 이름의 번역이 `rewards` 행이 아니라 `*_settings` 에 있어서,
  보상 화면이 왕복을 하나 더 한다 (`src/lib/repo/quiz.ts`·`stamp.ts` 의 `myReward`).
- **왜 미뤘나:** 대안은 `rewards.label_i18n` 을 두고 `reward_claim` 이 박제하는 것인데,
  **그 함수는 스탬프·모의고사·포토카드가 같이 쓴다.** 이름 하나 옮기자고 열 자리가 아니다.
  보상 화면은 방문자당 몇 번 안 열려 실측 비용도 작다.
- **언제 다시 볼까:** `reward_claim` 을 다른 이유로 고칠 때 같이. 또는 보상 화면이
  자주 열리는 서비스가 생기면.

## 4. `useLocalizedDisplay` 가 `i18n` 키를 결과에 남긴다

- **무엇을:** 훑는 루프에서 건너뛸 뿐, 반환 객체엔 `i18n` 이 그대로 있다
  (`src/i18n/display.ts`).
- **왜 미뤘나:** 지금은 무해하다 — 어느 화면도 `display` 를 DOM 속성으로 펼치지 않는다.
  지우면 타입이 `T` 가 아니게 되어 호출부가 다 바뀐다.
- **언제 다시 볼까:** `{...display}` 로 펼치는 코드가 처음 생길 때. 그때는 반드시 지운다.

## 5. 넓은 폭 누출 검사가 영어 한 언어만 돈다

- **무엇을:** `verify-i18n-leak` 의 1280px 패스는 `langs: ['en']` 이다.
- **왜 미뤘나:** 여기서 찾는 **감싸기 누락**은 언어를 안 탄다(어느 언어로 열든 한국어가 뜬다).
  "사전에 키는 있는데 특정 언어만 빈" 경우는 `i18n-parity` 가 따로 본다.
  세 언어를 다 돌면 시간만 세 배다.
- **언제 다시 볼까:** `i18n-parity` 가 못 보는 사전 구멍이 실제로 한 번이라도 나오면.

## 6. 모의고사 주관식 모범답안은 채점을 안 탄다

- **무엇을:** `quiz_answers.answers_i18n` 은 **보여줄 답**이지 **인정할 답**이 아니다.
  일본어로 적은 답을 맞다고 보려면 주최자가 `answers` 에 그 말을 더해야 한다.
- **왜 미뤘나:** 채점을 언어로 가르면 **같은 답이 언어에 따라 맞았다 틀렸다** 한다.
  더할 길은 이미 있다("오답 처리가 불만의 주된 원천이라 주최자가 나중에 더할 수 있다", 0024).
- **언제 다시 볼까:** 해외 방문자가 실제로 주관식에서 막히는 사례가 나오면.
  그때도 채점 규칙이 아니라 **주최자 화면의 안내**를 먼저 고친다.

## 7. 배열 방식과 항목별 사전 방식이 섞여 있다

- **무엇을:** 스탬프 칸은 항목마다 자기 사전(`StampCell.nameI18n`), 모의고사 보기는
  언어당 배열 하나(`choicesI18n`)다. 전자는 순서가 바뀌어도 안 어긋나고, 후자는 어긋난다.
- **왜 미뤘나:** 배열을 고른 근거가 있다 — 보기는 **순서가 곧 정답 인덱스**라
  (`quiz_answers.answers` 가 `'0'`·`'2'` 로 가리킨다) 한 덩어리로 둬야 줄이 안 갈린다.
  다만 그 선택이 삭제·재정렬을 **호출자 책임**으로 만든다 (실제로 삭제에서 한 번 터졌다).
- **언제 다시 볼까:** 보기 순서를 바꾸는 UI(드래그 정렬)를 넣을 때. 그때 반드시 같이 민다.

## 8. 럭키드로우·타로·모의고사는 헤더 통일 대상이 아니다

- **무엇을:** `verify-header-uniform` 은 일곱 서비스만 본다. 나머지 셋은
  `ServiceHeader` 를 안 쓰고 자기 무대를 그린다.
- **왜 미뤘나:** 무대형 화면(덱·부채·시작 화면)은 제목이 화면 가운데에 오는 게 설계다.
  헤더 규칙(위 24·좌우 20·19px)을 씌우면 그 연출이 깨진다.
- **언제 다시 볼까:** 세 서비스의 화면 구조를 다시 잡을 때.

## 9. 편집기 UI 라벨은 한국어 고정

- **무엇을:** 슬롯 편집기(`/theme-editor`)의 라벨·안내는 번역하지 않는다.
  입력**값**만 다국어 대상이다.
- **왜 미뤘나:** 미룬 게 아니라 **설계다** (`src/i18n/index.tsx` 머리말 — 쓰는 사람이
  우리 하나다). 여기 적는 이유는 "빠뜨린 것" 으로 오해받지 않기 위해서다.
- **언제 다시 볼까:** 편집기를 우리 아닌 사람에게 열 때.
