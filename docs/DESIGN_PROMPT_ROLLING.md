# 롤링페이퍼 디자인 프롬프트

Claude(claude.ai)에 아래 `---` 사이 내용을 그대로 붙여넣으면 롤링페이퍼 화면 시안이 아티팩트로 생성됩니다.
시안 확인 후 마음에 드는 방향이 나오면 그 결과를 구현 단계의 레퍼런스로 씁니다.

**이 프롬프트의 의도 (중요)**
- **레이아웃·구성·반응형·질감만** 뽑는 게 목적이다. 색·폰트·크기·radius 같은 **디자인 토큰은 일부러 정하지 않는다** — 실제 값은 이벤트(슬롯)마다 우리 디자인 시스템에서 런타임에 입히고, **주최자가 폰트·글자색·배경색·테두리색·테두리 유무까지 고른다**(럭키드로우와 동급의 커스터마이즈).
- 그래서 시안은 **중립 플레이스홀더 색**으로만 그려지고, 평가 기준도 색이 아니라 배치·비례·반응형·"포스트잇 벽" 감성이다.

**사용 팁**
- 한 번에 안 나오면 "포스트잇을 더 겹치게", "데스크톱에서 벽을 더 넓게", "테이프를 더 사실적으로" 같은 후속 요청으로 다듬으세요.
- 작성 페이지 배치가 마음에 안 들면 "작성 페이지를 더 집중되게" / "돌아가기를 더 크게" 처럼 방향만 바꿔 재요청하세요.

---

너는 모바일·데스크톱 웹 UI 디자이너다. 아이돌 생일카페 이벤트의 **롤링페이퍼(응원 메시지 벽)** 화면 시안을 만들어라.

## 산출물

- **단일 HTML 아티팩트** 하나. 인라인 CSS만 쓰고 외부 리소스(CDN·폰트·이미지)를 절대 불러오지 마라 — 아티팩트에서 차단된다.
- 화면은 **두 개**다 — ①벽(메시지가 쌓이는 곳) ②작성 페이지(메시지를 쓰는 별도 화면). 둘 다 그려라.
- **반응형이 핵심이다.** 벽은 세 폭에서 어떻게 보이는지 다 보여줘라(모바일 390px · 태블릿 834px · 데스크톱 1280px+). 작성 페이지는 최소 모바일 + 데스크톱 두 폭.
- 실제 동작 앱이 아니라 **정지 시안**이다. hover 정도만 CSS로 표현해도 좋다.
- 일러스트·사진은 넣지 마라. 스티커·이미지가 들어갈 자리는 **회색 플레이스홀더 박스**로 표시해라.

## 이건 무엇인가 (맥락)

- 생일카페에 온 팬들이 **최애에게 응원 한마디를 남기는 공개 벽**이다. 남기면 **즉시** 벽에 붙고, 벽은 실시간으로 채워진다(옆 사람이 남긴 것도 곧 올라온다).
- 쓰는 기기가 하나가 아니다: 방문자는 **자기 폰**으로 남기기도 하고, 부스에 놓인 **태블릿·PC**로 다 같이 벽을 구경하기도 한다. **그래서 큰 화면에서도 살아 있어야 한다** — 지금은 모바일 확대판처럼 좁아서 프로토타입 같다. 데스크톱에선 벽이 **넓은 게시판**이 돼야 한다.
- **남기는 행위는 벽과 분리된 별도 페이지에서 한다.** 벽에서 "남기기"를 누르면 작성 페이지로 넘어가고, 다 쓰면 벽으로 돌아온다. (벽 위에 입력폼을 얹지 마라 — 벽은 읽고 구경하는 곳, 작성은 집중하는 곳으로 나눈다.)
- 분위기: 진짜 롤링페이퍼 — **코르크보드/벽에 포스트잇을 테이프로 붙여둔** 따뜻하고 북적이는 느낌. 반듯하게 정렬된 카드 그리드는 프로토타입처럼 보인다. **손으로 붙인 듯 살짝 삐뚤빼뚤하고, 높이가 제각각이고, 서로 조금씩 겹쳐 보이는** 게 이 화면의 인상 전부다.

## 핵심 컨셉: 포스트잇 벽 (이걸 못 살리면 실패다)

- 메시지 한 개 = **포스트잇 한 장.** 정사각에 가까운 종이 쪽지, 아래로 살짝 두꺼워지는 종이 그림자, 미세한 랜덤 회전(대략 -3°~+3°)으로 손으로 붙인 티가 나게.
- 각 포스트잇 위에 **반투명 마스킹 테이프 조각**이 비스듬히 하나 붙어 "벽에 붙여둔" 느낌을 준다. 일부는 위쪽 가운데 한 조각, 일부는 양쪽 위 귀퉁이에 두 조각 — **전부 똑같지 않게** 변주해라.
- 포스트잇은 **몇 가지 파스텔 톤**을 섞어 쓴다(색은 중립 플레이스홀더로 — 실제 색은 우리가 입힌다). 색이 다양해야 벽이 북적여 보인다.
- 종이 느낌 디테일: 아주 옅은 종이 질감/접힌 모서리(dog-ear) 정도는 좋다. 단 과하지 않게 — 읽는 데 방해되면 안 된다.

## 색·폰트·크기 (여기서 정하지 마라 — 전부 교체 가능해야 한다)

- **구체적 브랜드 색·hex·폰트·크기·radius 를 고정하지 마라.** 실제 토큰은 이벤트마다 런타임에 갈아끼워진다.
- 특히 이 요소들은 **주최자가 고르는 값**이라 시안에선 **교체 가능한 플레이스홀더**로만 두고 하드코딩하지 마라: **폰트(글꼴)** · **글자색** · **배경색** · **테두리색** · **테두리 유무(있음/없음)**. 테두리가 없는 버전도 배경만으로 요소가 구분되게 설계해라.
- 중립 플레이스홀더(파스텔 포스트잇 몇 종 + 은은한 보드/벽 배경)로만 그려라. 비례·여백·리듬은 네 판단으로 자연스럽게.
- **아이콘은 Lucide 아이콘만** 쓰고, SVG 를 인라인으로 직접 그려 넣어라(외부 스크립트 로드 금지, stroke-width 1.5~2). **이모지 사용 절대 금지.** 예: 돌아가기 `arrow-left`, 남기기 `pencil`/`plus`, 관리자 `settings`, 스티커 자리 `sticker`.

## 화면 사양

### 화면 ① 벽

위에서 아래로:

**1. 벽 헤더**
- 벽 **제목**을 크게. 제목은 **고정 문구가 아니라 주최자가 정하는 편집 가능한 값**이다 — "롤링페이퍼"로 박아두지 말고 플레이스홀더(예: "○○ 생일 축하 롤링페이퍼")로 두고, 짧은/긴 제목 모두 깨지지 않게. 그 아래 한 줄 안내(예: "따뜻한 한마디를 남겨 주세요")도 편집 가능한 플레이스홀더.
- **관리자 진입**: 벽 구석(예: 아주 아래, 또는 헤더 끝)에 **방문자 눈엔 잘 안 띄는 흐릿한 "관리자" 링크**를 하나 둬라. 주최자만 찾아 눌러 관리자 로그인으로 간다. 크거나 화려하면 안 된다.

**2. "남기기" 진입 (벽 → 작성 페이지)**
- 벽에서 **눈에 잘 띄는 "남기기" 버튼**을 둬라. 누르면 **작성 페이지(화면 ②)로 이동**한다. (모바일에선 화면 하단 고정 버튼, 데스크톱에선 헤더 또는 우하단 플로팅 등 — 벽을 가리지 않으면서 항상 손 닿는 자리.)

**3. 메시지 벽 (핵심)**
- 포스트잇들이 **메이슨리(높이 제각각, 위에서 아래로 채우는 컬럼)**로 쌓인다. 반응형 컬럼 수:
  - 모바일 **2열** → 태블릿 **3~4열** → 데스크톱 **5~6열** (넓을수록 열을 늘려 벽처럼)
- 포스트잇 한 장의 구성: **본문 텍스트**(길이 제각각) · 있으면 **남긴 이름**("— 이름", 아래 오른쪽) · 선택적 **스티커**(귀퉁이에 플레이스홀더) · **테이프**.
- 반듯한 격자가 아니라 **살짝 어긋난 배치**로. 회전·색·테이프 위치가 카드마다 달라 북적이게.
- **빈 상태**(아직 아무도 안 남김): 벽 한가운데 "첫 메시지를 남겨 보세요" 를 포스트잇 한 장 느낌으로 외롭게.

### 화면 ② 메시지 작성 페이지 (벽과 분리된 집중 화면)

- 벽에서 "남기기"로 진입하는 **별도 페이지**다. 벽의 북적임과 달리 **차분하고 집중되는** 화면.
- 상단에 **"돌아가기"**(← 벽으로) + 짧은 안내("메시지 남기기").
- 입력: **이름(선택)** · **메시지(여러 줄, 이 화면의 주인공 — 넉넉히)** · **쪽지 색 고르기(작은 스와치 몇 개 중 택1)** · **스티커 고르기(플레이스홀더 썸네일 중 택1, 선택)**.
- 아래에 **"남기기" 제출 버튼**. 누르면 벽으로 돌아가 방금 쓴 포스트잇이 붙어 있는 흐름(시안에선 제출 후 상태를 따로 그릴 필요는 없다).
- **작성 중 내 포스트잇 미리보기**를 곁에 보여주면 좋다(선택): 고른 색·이름·본문이 실제 포스트잇 모양으로 미리 보이면 즐겁다.
- 데스크톱에선 폼을 화면 가운데 카드로 모아 집중되게(벽처럼 넓게 펴지 말 것).

### 반응형 거동 (명시적으로 다 보여줘라)
- **모바일 390px**: 벽은 2열 + 하단 고정 "남기기". 작성 페이지는 전체 폭 폼.
- **태블릿 834px**: 벽 3~4열. 화면을 시원하게 채운다.
- **데스크톱 1280px+**: 벽은 5~6열의 **넓은 게시판**(좌우 여백 과하지 않게, 포스트잇은 읽기 좋은 크기 유지). 작성 페이지는 가운데 모인 카드.

## 흐름

벽(구경) → **"남기기"** → 작성 페이지(집중해서 씀) → 제출 → 벽으로 복귀(내 포스트잇이 붙어 있음).

## 톤 & 카피

- 존댓말 해요체, 다정하고 들뜬 축하 분위기. 무섭거나 위압적인 표현 금지.
- 예시 문구는 **플레이스홀더**다(자유 교체): 제목 "○○ 생일 축하 롤링페이퍼", 안내 "따뜻한 한마디를 남겨 주세요", 버튼 "남기기". 포스트잇 본문도 짧은 축하 문구 몇 종을 길이만 다르게 채워라.

## 마지막 체크

제출 전 스스로 확인해라:
- **벽과 작성이 별도 화면**이고, 벽의 "남기기"가 작성 페이지로 가는가? (벽 위에 입력폼을 얹지 않았는가)
- 포스트잇이 **테이프로 붙은** 느낌이고, 회전·색·테이프가 카드마다 달라 북적이는가?
- 반듯한 그리드라 **프로토타입처럼** 보이지 않는가? (살짝 어긋나 있는가)
- **데스크톱에서 벽이 넓은 게시판**으로 살아 있는가? (모바일 확대판이 아니라)
- 제목이 "롤링페이퍼"로 박히지 않고 **편집 가능한 플레이스홀더**인가? 긴 제목도 안 깨지는가?
- 벽에 **방문자 눈엔 안 띄는 관리자 진입**이 있는가?
- 색·폰트·**테두리(있음/없음 포함)**를 하드코딩하지 않고 교체 가능한 플레이스홀더로 뒀는가? 테두리 없는 버전도 성립하는가?
- 이모지 없이 **인라인 Lucide SVG 아이콘**만 썼는가?
