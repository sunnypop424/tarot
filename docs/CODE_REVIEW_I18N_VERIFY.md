## 위반 분석

### 위반 1

- **위반 종류:** 톤 / 금지
- **Rule 근거:** `code-review-tutoring.md: 금지` — "개인 평가/감정 표현/동기부여 문장 금지 …
  대신 '관찰→근거→영향'으로만 기술"
- **위반 내용:** 5-2 의 관찰이 "만든 검사를 **일부러 실패시켜 보고** 헛도는 것을 찾아 고쳤다" 로
  **작성자의 행위**를 서술한다. 같은 항목의 "사람 눈 말고는 잡을 길이 없던 것을 기계가 잡게 됐다"
  도 코드 사실이 아니라 작업 과정에 대한 평가다. 7-2 의 목표 문장
  "검사를 만들면 반드시 한 번은 실패시켜 본다" 역시 코드가 아니라 사람의 습관을 대상으로 한다.
- **영향:** 강점 항목이 "코드 수준 사실"(Rule 5번 섹션 규칙)이 아니라 작업 서사가 되어,
  다음 리뷰와 같은 축으로 비교할 수 없다. 학습 방향성도 PASS/FAIL 판정 대상이
  코드가 아닌 행위가 되어 판정이 주관에 열린다.
- **조치:** 5-2 의 관찰을 코드 사실로 좁힌다 — 예: "`verify-i18n-select.mjs` 는 `.select()`
  리터럴과 `const COLS/SELECT` 상수를 함께 모아 검사 대상으로 삼는다(`all.length === 0` 가드)."
  실패시켜 본 경위는 근거란이 아니라 삭제하거나, 코드에 남은 흔적(가드 주석)만 근거로 인용한다.
  7-2 는 "검사 스크립트는 대상 개수를 함께 출력한다" 처럼 **산출물로 판정 가능한** 목표로 바꾼다.

### 위반 2

- **위반 종류:** 근거
- **Rule 근거:** `code-review-tutoring.md: 증거 규칙(강제)` — "모든 지적/평가는
  (파일경로:라인범위) 또는 (함수/클래스 이름)로 근거를 명시한다."
- **위반 내용:** 1) 결론의 근거 목록이 검증 스크립트의 **실행 결과 수치**만 적고
  파일경로·라인·함수명을 달지 않았다(`verify-i18n-leak` 0종 등).
  3-2 의 근거는 `src/lib/repo/quiz.ts` `myReward` 로 함수명은 있으나 라인범위가 없고,
  6-2 의 근거 `src/data/stamp.ts` `StampCell` 역시 라인범위가 없다.
  5-1·5-3 도 일부 항목만 라인범위를 갖고 나머지는 파일명+함수명이다.
- **영향:** Rule 은 파일경로:라인범위 **또는** 함수/클래스명을 허용하므로 함수명만 있는 항목은
  형식상 통과지만, 결론 섹션의 수치 근거는 둘 중 어느 형태도 아니다. 결론의 상태 판정
  ("조건부 통과")이 재확인 불가능한 근거 위에 서 있다.
- **조치:** 결론의 각 수치에 그 수치를 내는 스크립트 경로를 명시한다
  (예: `scripts/verify-i18n-leak.mjs` → 0종). 또는 그 줄들을 근거가 아니라
  "실행 기록" 으로 분리해 근거 목록에서 뺀다.

### 위반 3

- **위반 종류:** 섹션
- **Rule 근거:** `code-review-tutoring.md: 출력 형식(강제)` — 8) 항목은
  "@path2가 제공된 경우에만"
- **위반 내용:** 대상 리뷰는 단일 경로 모드라고 0) 범위에서 밝혔음에도 8) 섹션을 출력하고
  본문에 "근거 불충분" 을 적었다.
- **영향:** 경미하다. 다만 Rule 의 조건부 섹션을 조건 불충족 상태에서 출력하면,
  섹션 존재 여부로 모드를 판별하는 후속 자동 검사가 오판할 수 있다.
- **조치:** 8) 섹션을 통째로 생략하거나, 0) 범위에만 "비교 분석 미수행(근거 불충분)" 을 남긴다.
  (`code-review-tutoring.md: 입력 모드(강제)` 가 "근거 불충분으로 적고 비교 분석을 수행하지 않는다"
  라고만 하여 섹션 출력 여부는 명시하지 않으므로, 둘 중 하나로 고정한다.)
