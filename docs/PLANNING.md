# 타로카드 모바일 웹 — 서비스 기획서

## 1. 서비스 컨셉

**아이돌 생일카페 이벤트 페이지를 파는 플랫폼.** 팬이 카페에서 QR을 찍고 바로 카드를 뽑는, 회원가입도 로딩도 없는 초경량 모바일 웹.

### 슬롯 구조 — 배포 하나에 여러 이벤트

배포 하나가 여러 이벤트를 담는다. 이벤트마다 **슬롯**을 하나씩 갖고, 슬러그가 그 이벤트의 루트가 된다.

```
/starlit-rian          스타릿 리안 슬롯 (그 이벤트의 홈)
/starlit-rian/admin    리안 주최자만 관리
/moonset-haon            문셋 하온 슬롯
/                        아무것도 없음 — 슬롯 목록을 노출하면 남의 이벤트가 다 보인다
```

**역할이 둘로 나뉜다:**

| | 플랫폼 소유자 | 이벤트 주최자 (고객) |
|---|---|---|
| 하는 일 | 슬러그·테마·이미지를 받아 설정해 배포, **주최자 계정 발급** | 자기 슬롯의 질문·답변 관리 |
| 도구 | 슬롯 편집기 `/theme-editor` (**Supabase 가 설정된 빌드에만 존재**) | 관리자 `/{slug}/admin` |
| 편집 대상 | 색·radius·이미지·플랜·이벤트 설정 + 주최자 계정 | 질문 타로의 질문 + 카드별 답변, 자기 비밀번호 |
| 저장 | DB — **저장하기가 곧 배포다** | 백엔드 (즉시 저장, 모든 방문자에게 반영) |

**격리가 이 구조의 전부다.** 리안 관리자가 하온 슬롯을 건드릴 수 없어야 하므로 테마·질문·관리 권한이 전부 슬러그로 스코프된다 (`src/lib/repo/`의 모든 메서드가 slug를 받는다).

- 카테고리 선택 → 카드 뽑기 → 해석 열람까지 **3탭 이내**
- 78장 전체 의미 데이터를 번들에 내장 — 카드 뽑기는 네트워크 없이 동작한다
- `localStorage`로 기간별 뽑은 카드 유지 (오늘=자정 / 주간=월요일 / 월간=1일 리셋)
- **질문 타로만 원격 데이터** (주최자가 실시간으로 고치므로). 카페 와이파이가 불안정할 때를 대비해 번들된 질문으로 폴백한다

### 슬롯이 갈아끼우는 것 (§5 테마 시스템)

소유자가 슬롯마다 정해 배포한다 — 주최자는 못 바꾼다.

| 항목 | 내용 |
|---|---|
| 색 | 배경, 표면, 인터랙션(primary), 장식(accent), 텍스트, 보더 (17개) |
| 형태 | radius (미세/버튼·토스트/카드·타일) |
| 배경 패턴 | 이미지 URL + 불투명도·크기·반복 |
| 로고 | 이미지 URL + 대체텍스트·높이 |
| 카드 이미지 | 앞면 경로 규칙 + 뒷면 URL |
| 이벤트 설정 | 카테고리별 뽑는 수(1/3)·덱 범위·역방향 |

기본 테마(보라 미스틱)는 어디까지나 폴백이다.

### 핵심 원칙
1. **가볍게:** 프레임워크 최소 구성(React + Vite), 이미지 최적화, 3D 라이브러리 없이 CSS transform만으로 카드 연출
2. **단정하지 않게:** 운세는 예언이 아니라 "흐름과 조언" — 공포 조장·과몰입 유도 금지
3. **테마로 열어둘 것:** 색·이미지는 전부 토큰. 컴포넌트에 hex를 박는 순간 다음 이벤트에서 못 쓴다
4. **현장에서 30초:** 카페 대기줄에서 뽑고 읽는다. 로딩이 길면 안 쓴다

## 2. 카테고리 구성

기간 운세(홈)와 주제별 운세(운세 탭) 모두 같은 뽑기 플로우를 쓴다 — `src/data/categories.ts` 한곳에 정의.

| 카테고리 | 기본 | 포지션 | 비고 |
|---|---|---|---|
| 오늘 | 1장 | 오늘의 메시지 | 기간 잠금: 자정 |
| 주간 | 1장 | 이번 주의 흐름 | 기간 잠금: 월요일 |
| 월간 | 1장 | 이달의 키워드 | 기간 잠금: 1일 |
| 애정운 | 1장 (관리자가 3장 선택 가능) | 관계의 흐름 / *3장: 나의 마음·상대의 마음·관계의 흐름* | |
| 금전운 | 1장 (3장 가능) | 돈의 흐름 / *3장: 현재 상황·장애물·조언* | |
| 직업·학업운 | 1장 (3장 가능) | 지금 이 길 / *3장: 현재 위치·다가올 가능성·조언* | |
| 예 / 아니오 | 1장 | 답 | 판정 + 간단 설명 + 기존 해석 |

- 역방향 노출 확률: 기본 **30%** (카드별 균등)

### 왜 기본이 1장인가

카드 의미 데이터는 **한 장짜리 완결 해석**으로 쓰여 있다. 그래서 3장을 나열하면 서로 무관한 세 덩어리가 되고, 정작 필요한 "그래서 종합하면?"이 없다. 포지션별 텍스트를 따로 쓰려면 78장 × 3포지션 × 정/역 = 468개를 더 써야 해 현실적이지 않다.

→ **기본 1장.** 3장은 관리자가 켤 수 있게 두되, 각 장을 짧게(포지션 + 키워드 + 조언 한 줄)만 보여준다. **제대로 된 종합은 AI 연동(M4) 때 붙인다** — 정적 데이터로 억지 종합을 만들면 어차피 어색하다.

### 예/아니오 판정 (`src/data/yesno.ts`)

- 메이저 22장은 번호별 판정을 명시, 마이너는 수트 기본 성향(완드·컵·펜타클 = 예 / 소드 = 아니오) + 예외 카드로 정한다
- **역방향은 답을 뒤집는다** (예↔아니오, 글쎄요는 유지) — 가장 직관적이고 예/아니오 분포도 균형을 유지한다
- **답이 먼저지만 거대하게 띄우지 않는다.** 해석 영역 맨 앞에 조언과 같은 디자인(세로선 블록)으로 "예 + 한 줄" → 그 아래 기존 해석. 색으로 겁주지 않는다 — 아니오도 에러 레드가 아니다

### 카드 뽑기 인터랙션 (덱 펼치기 → 셔플 → 직접 선택)

**"내가 고른 카드"라는 감각이 이 서비스의 핵심 리추얼**이다. 시스템이 카드를 정해 보여주는 게 아니라, **덱 전체를 뒷면으로 펼쳐놓고** 그중에서 사용자가 직접 손으로 고른다. 실제 타로 리딩에서 리더가 카드를 부채꼴로 쫙 펼쳐 내미는 그 순간을 그대로 옮긴다.

**플로우:**
1. **펼치기:** 카드를 뒷면으로 부채꼴 배열 (기본: 메이저 22장 전부가 화면에 쫙 펼쳐짐 — 아래 "펼치는 카드 수" 참조)
2. **셔플:** 상단/하단의 셔플 버튼(Lucide `shuffle`)으로 언제든 다시 섞기 — 카드들이 흩어졌다 다시 모이는 연출 (1.2초, 스킵 가능). **횟수 제한 없음** — 마음에 들 때까지 섞는 것도 리추얼의 일부
3. **선택:** 펼쳐진 카드 중 아무거나 탭해 필요한 수(1~3장)만큼 선택 — 고른 카드는 아크에서 위로 뽑혀 나오며 보라 글로우 + 순서 배지(3장 스프레드는 포지션 순서와 매칭)
4. **공개:** 필요한 수를 다 고르면 "결과 보기" CTA 활성화 → 고른 카드만 순차 플립 (0.15s stagger)

**펼치는 카드 수 (관리자 설정):**
- **미지정(기본값): 메이저 22장 전부를 펼침** — 별도 후보 추출 없이 덱을 통째로 내미는 형태
- 관리자가 질문별로 펼침 수를 직접 지정 가능 (`spreadCount`, **3~78**). 지정 시 덱 설정 범위에서 그 수만큼 중복 없이 추출해 펼침 (예: 10 → 10장만 펼쳐놓고 그중 선택)
- 검증 조건: `spreadCount ≥ 뽑는 수 + 2` — 펼친 수가 뽑는 수와 가까우면 고르는 의미가 사라짐. 덱 범위가 메이저(22)인데 `spreadCount`가 22를 넘을 수 없음
- 기본 카테고리(오늘의 타로, 애정운 등)는 미지정 기본값(메이저 22장 전부)을 사용

**규칙:**
- 각 카드의 정/역방향은 셔플 시점에 결정되며, 고르는 순간엔 사용자가 알 수 없음 (뒤집을 때 드러남)
- **고르지 않은 카드는 절대 공개하지 않음** — "안 고른 카드는 뭐였지?"라는 여백이 리추얼의 일부
- 선택 취소 가능(선택된 카드 재탭 시 해제), 필요한 수를 다 고르기 전까지 결과 화면 진입 불가
- 선택 중 셔플하면 선택이 초기화됨 (확인 토스트)

**펼침 레이아웃 — 부채꼴 여러 줄** (구현: `src/components/DeckSpread.tsx`)

한 줄이 하나의 부채꼴이다. 카드를 같은 자리에 겹쳐 두고 **카드 아래 먼 지점을 축으로 회전**시키면 회전만으로 좌우 퍼짐과 아래로 처지는 호가 함께 나온다 — 손에 쥔 카드를 편 모양.

- **제1 제약: 덱 + 슬롯 + CTA 가 한 화면에 들어온다.** 작은 기기(375×667)에서도. 이게 깨지면 카드를 더 줄이기보다 줄당 장수를 늘린다
- **줄 수는 화면 높이에 반응** — 760px 이상이면 3줄, 미만이면 2줄 (22장 기준 8·8·6 / 11·11)
- **줄끼리 세로로 겹친다** (52px). 아랫줄이 윗줄 위로 올라오도록 줄마다 쌓임 맥락(z-index)을 준다
- **각도 간격은 "꽉 찬 줄" 기준으로 고정**하고 줄마다 0°를 중심으로 대칭 배치 — 장수에 맞춰 각도를 다시 나누면 마지막 줄만 간격이 벌어져 따로 논다
- 한 줄 상한 12장 (넘으면 노출 폭이 좁아 고르기 어려움) → 전체 78장 같은 큰 덱은 한 화면을 포기하고 스크롤
- 짚은 카드는 살짝 떠오르고(`translateY(-14px)`) 그 줄이 통째로 앞으로 나온다
- 성능: 카드 뒷면은 단일 SVG 재사용, `transform`/`opacity`만 애니메이션

**선택 슬롯 (덱 아래)**
- 뽑는 수만큼 점선 빈 칸 + 포지션 라벨. 라벨은 카드 유무와 무관하게 항상 자리를 차지한다 — 안 그러면 카드가 얹힐 때 아래 버튼이 덜컹 밀린다
- 고른 카드는 덱의 원래 위치에서 슬롯으로 날아가 얹힌다 (FLIP, 420ms). 덱에서는 그 카드 자리를 비우되 재배치하지 않는다
- 얹힌 카드의 X 버튼으로 물러서 다시 고를 수 있다

**셔플 연출** — 카드가 쓸려 나갔다가(gather 420ms) 한 장씩 다시 부채꼴로 놓인다(deal 780ms). 선택은 초기화된다.

### 커스텀 질문 (관리자 등록)

기본 카테고리 외에, 관리자가 직접 등록한 질문에 카드를 뽑아 답을 보는 기능.

- **사용자 플로우:** 홈 "질문 타로" 섹션 → 질문 목록에서 선택 (예: "이직해도 될까요?") → 설정된 덱 범위로 카드 뽑기 → 해당 질문 × 카드 조합의 답변 표시
- **답변 소스 우선순위:**
  1. 관리자가 직접 입력한 답변 (질문 × 카드 × 방향별)
  2. 미입력 시 폴백: 카드 기본 의미 중 질문에 설정된 관점(애정/금전/직업/종합) 텍스트
  3. (추후) AI 생성 답변 — AI API 연동 시 관리자 페이지에서 일괄 생성
- **질문별 덱 설정** (관리자가 지정):
  - 카드 범위: 메이저 22장만 / 전체 78장
  - 역방향: 사용 안 함 / 사용 (확률 지정, 기본 30%)
  - 뽑는 카드 수: 1~3장
  - 펼치는 카드 수: 미지정 시 **메이저 22장 전부**, 지정 시 3~78장

## 3. 기간 운세 (홈 — 오늘 / 주간 / 월간)

세그먼트로 전환하는 단일 화면. 셋은 **뽑는 주기만 다른 같은 것**이라 한곳에 묶었다.

| 구분 | 구성 | 갱신 주기 | 기간 키 |
|---|---|---|---|
| 오늘 | 1장 + 애정·금전·직업 한 줄 요약 | 매일 자정 | `YYYY-MM-DD` |
| 주간 | 1장 + 한 줄 요약 | 매주 월요일 | ISO 주차 `YYYY-Www` |
| 월간 | 1장 + 한 줄 요약 | 매월 1일 | `YYYY-MM` |

**전부 직접 뽑는다.** 오늘·주간·월간도 결국 같은 뽑기 플로우라 카테고리로 통합했고(`src/data/categories.ts`), 다른 점은 **기간마다 한 번만** 뽑을 수 있다는 것뿐이다 — `period` 필드가 그 잠금을 건다.

**기간을 여러 장으로 쪼개지 않는다.** 월간을 1~4주차로 나눠 4장 보여주는 건 과했다. 한 달의 흐름은 한 장으로 충분하고, 카드가 많아질수록 읽는 부담만 커진다. 주간도 같은 이유로 1장.

**결과 고정 방식:** 셔플과 펼침 배열은 매번 무작위여도 무방하다 — 사용자는 뒷면만 보므로 무엇을 고를지 예측할 수 없다. **고른 결과를 기간 키로 localStorage에 저장**(`src/lib/storage.ts`)해 그 기간 내내 고정하고, 기간 키가 바뀌는 순간 저장분이 무효가 되며 다시 열린다. 시드·기기 ID가 필요 없다.

## 4. 화면 구조 (IA)

하단 탭바 2개(홈 / 운세) + 헤더 우상단 도감 아이콘.

- **홈 = 기간 운세** (오늘·주간·월간). 매일 여는 리추얼이라 첫 화면에 둔다. 셋은 뽑는 주기만 다른 같은 것이라 세그먼트로 묶었다
- **운세 = 골라 뽑는 것** (주제별 + 질문 타로). 궁금할 때 들어오는 성격

```
홈  (탭) — 기간 운세
├─ 이벤트 로고
├─ 세그먼트: 오늘 / 주간 / 월간
└─ 각 기간: 안 뽑았으면 카드 뒷면(누르면 뽑기) + CTA
            뽑았으면 카드 + 해석 + 애정·금전·직업 한 줄 요약

운세  (탭) — 골라 뽑는 것
├─ 주제별 그리드: 애정운 / 금전운 / 직업·학업운 / 예·아니오
└─ 질문 타로 목록 (관리자 등록) → 질문별 덱 설정으로 뽑기 → 답변

카드 도감  (헤더 아이콘, 탭 아님)
├─ 목록: 메이저 / 완드 / 컵 / 소드 / 펜타클
└─ 상세: 카드 이미지 + 키워드 + 상징 + 정/역방향 전체 의미

기록 (v2): 최근 뽑은 카드 히스토리 (localStorage, 최근 30개)
/admin (숨김 라우트, 패스코드 보호) — 관리자 페이지
```

**카드 뽑기 플로우 (모든 카테고리 공통)**
1. 카테고리 안내 + 질문 떠올리기
2. 덱 펼치기(기본 메이저 22장) → 셔플(반복 가능) → 직접 선택 → 고른 카드가 아래 슬롯으로 날아가 얹힘 (슬롯의 X 로 물러서 다시 고르기)
3. 결과: 스크롤로 드러날 때 카드가 뒤집히며 포지션별 해석 + 종합 조언

## 4-1. 관리자 페이지 (/admin)

일반 내비게이션에 노출하지 않는 숨김 라우트. 간단한 패스코드로 보호 (정적 웹 특성상 완전한 보안은 아니며, 콘텐츠 관리 편의 목적).

### 기능
1. **질문 관리 (CRUD):** 질문 텍스트, 공개/비공개 토글, 폴백 관점(애정/금전/직업/종합), 뽑는 카드 수
2. **테마 편집:** 색·로고·배경패턴·카드 이미지 (상세는 §5 테마 시스템)
3. **질문별 덱 설정:**
   - 카드 범위: `메이저만(22장)` / `전체(78장)`
   - 역방향: `사용 안 함` / `사용` (+확률 %)
   - **펼치는 카드 수:** 미지정(기본) = 메이저 22장 전부 / 지정 시 3~78장 — `펼침 수 ≥ 뽑는 수 + 2` 및 `펼침 수 ≤ 덱 범위 장수` 검증
   - → 설정에 따라 답변 입력 범위가 결정됨: 메이저만+정방향만이면 답변 22개, 전체+역방향이면 최대 156개
4. **답변 관리:** 질문 선택 → 카드 그리드(설정 범위만 표시) → 카드별 정/역방향 답변 텍스트 입력
   - 미입력 카드는 "폴백 사용 중" 표시 — 사용자에겐 카드 기본 의미의 해당 관점 텍스트가 노출됨
   - **"AI로 전체 생성" 버튼 자리 확보** (추후 AI API 연동 시 활성화: 질문+카드 의미를 컨텍스트로 일괄 생성 → 관리자 검수 후 저장)
5. **데이터 내보내기/가져오기:** 아래 저장 방식 참조

### 데이터 저장 방식 (정적 웹 유지 전제)
- **v1 (권장):** 관리자 페이지에서 편집한 내용을 브라우저 localStorage에 임시 보관 → `questions.json` / `themes.json` 파일로 **내보내기(다운로드)** → 레포 `src/data/`에 반영 후 재배포. 서버·DB 없이 유지되고, 사용자에겐 빌드에 포함된 데이터가 서빙됨
- **v2 (선택):** Supabase 등 경량 BaaS 연동 시 실시간 반영 — 재배포 없이 질문/답변 수정 가능. AI API 연동 시점에 함께 검토

### 질문 데이터 스키마 (초안)
```json
{
  "id": "q-001",
  "question": "지금 이직해도 괜찮을까요?",
  "published": true,
  "cardCount": 1,
  "deck": "major",            // "major" | "full"
  "spreadCount": null,        // null = 메이저 22장 전부 펼침 (기본) | 3~78
  "allowReversed": false,
  "reversedRate": 30,
  "fallbackAspect": "직업",    // 미입력 답변의 폴백 관점
  "answers": {
    "major-0": { "upright": "…", "reversed": "…" }
  }
}
```

### 주요 유저 플로우 — 애정운 예시
1. 홈에서 "애정운" 탭
2. 안내 문구("마음속 상대를 떠올려 보세요") → "카드 섞기"
3. 셔플 애니메이션(1.5s 이내) → 카드 팬에서 3장 탭
4. 선택 완료 → 카드가 순서대로 플립되며 포지션 라벨 표시
5. 스크롤로 포지션별 해석 → 하단 종합 조언 → "다시 뽑기" / "다른 운세 보기"

## 5. 테마 시스템

생일카페마다 앱의 옷을 갈아입힌다. 구현: `src/types/theme.ts`(스키마) · `src/data/themes.ts`(테마 목록) · `src/lib/theme.ts`(주입) · `src/theme/ThemeProvider.tsx`(적용).

### 동작 방식
`tokens.css`에 선언된 CSS 커스텀 프로퍼티가 기본값이고, `applyTheme()`이 런타임에 `document.documentElement`의 인라인 스타일로 덮어쓴다. 컴포넌트는 전부 `var(--color-*)`만 참조하므로 **코드 수정 없이 색이 바뀐다.**

테마 선택 우선순위: `?theme=<id>` 쿼리 → localStorage 저장값 → 기본 테마.
현장 배포 시 QR에 `?theme=이벤트id`를 박으면 그 카페 전용 화면이 열린다.

### 테마로 바뀌는 것 / 안 바뀌는 것

| 바뀜 (이벤트 종속) | 안 바뀜 (제품 정체성) |
|---|---|
| 색 전체 (배경/표면/인터랙션/포인트/텍스트/보더) | 타이포 스케일·웨이트 |
| 배경 패턴 이미지 (+불투명도·크기·반복) | 스페이싱·라운드·터치 타깃 |
| 로고 이미지 | 모션 duration·easing |
| 카드 앞면/뒷면 이미지 | 레이아웃 구조, 카드 63:88 비율 (실물 규격 — `src/lib/card.ts`) |
| 커스텀 질문·답변 | 78장 카드 의미 데이터 |

### 색 이름은 역할 기반
`gold` 같은 색 특정 이름은 테마가 바뀌는 순간 거짓말이 된다. 그래서:
- `--color-primary` — **인터랙션**: CTA, 활성 탭, 선택 글로우
- `--color-accent` — **장식·포인트**: 카드 테두리, 아이콘, 별 문양 (기본 테마에선 골드)
- `--color-error`는 테마와 무관하게 고정 (시스템 에러 전용)

글로우 그림자(`--shadow-glow`)는 `primary`에서 자동 파생되므로 테마가 바뀌면 글로우도 따라간다.

### 카드 이미지
- **뒷면:** `assets.cardBack` 이미지가 있으면 사용, 없으면 내장 SVG 뒷면(방사형 바탕 + 포인트색 별 문양)으로 폴백
- **앞면:** `assets.cardFrontBase` + 카드 id로 경로 조합 — `{base}/{cardId}.{ext}` (예: `/themes/xxx-2026/cards/major-0.webp`). 78장을 이 규칙으로 넣으면 자동 매칭
- 이미지 미제공 이벤트도 동작해야 하므로 앞면 없으면 텍스트 표시로 폴백

### 로고
- 메인 히어로 상단 중앙. 이미지가 없으면 `logoAlt`(이벤트명) 텍스트로 대체 — **현재 임시 상태**
- 높이만 지정하고 폭은 auto (로고 비율 보존)

### 테마 스키마
```ts
{
  id: 'xxx-2026',
  name: '○○ 생일카페 2026',
  colors: { canvas, surface, surfaceRaised, wash, primary, primaryHover, primarySoft,
            accent, accentSoft, fg1, fg2, fg3, border, borderHover, onPrimary,
            cardBackFrom, cardBackTo },
  assets: { logo, logoAlt, logoHeight,
            backgroundPattern, backgroundPatternOpacity, backgroundPatternSize, backgroundPatternRepeat,
            cardFrontBase, cardFrontExt, cardBack },
}
```

### 관리자 테마 편집 (M3)
- 색 피커로 각 색 지정 + 라이브 프리뷰
- 로고·배경패턴·카드 이미지 업로드
- `themes.json` 내보내기 → 레포 반영 후 재배포 (질문 데이터와 동일한 방식)
- **대비 검증 필요:** 주최자가 고른 색이 텍스트 가독성을 깨뜨릴 수 있다. 배경 대비 텍스트 명도차를 경고로 표시

## 6. 데이터 설계

### 카드 의미 데이터
- 원본: `docs/cards/*.md` 5개 파일 (메이저 22 + 수트별 14×4 = 78장)
- 모든 카드 동일 필드:
  - 기본: 이름(한/영), 아르카나, 수트, 번호, 키워드
  - **상징:** 카드 그림·상징 묘사 (방향 무관, 중립 서술체) — 도감 설명 + AI 참고 자료
  - 정방향/역방향 각각: **핵심**(카드 자체의 본질 의미, 관점 무관, 중립 서술체) + {종합, 애정, 금전, 직업, 조언}(운세 화법)
- 구현 단계에서 md → `src/data/cards.json` 변환 스크립트 작성 (필드 구조가 균일하므로 기계 변환 가능)
- **필드 역할 구분:** 종합~조언은 사용자에게 그대로 노출되는 운세 텍스트, 상징·핵심은 ① 카드 도감 상세 ② 추후 AI 답변 생성 시 프롬프트 컨텍스트(질문 + 뽑힌 카드의 상징·핵심을 재료로 답변 생성)로 사용

### 해석 조합 로직
- 카테고리별 해석 = 카드의 해당 관점 텍스트(애정/금전/직업/종합)를 포지션 라벨과 조합
- 오늘의 운세 한 줄 요약 = 해당 카드의 관점별 텍스트 첫 문장 추출

### 커스텀 질문 데이터
- `src/data/questions.json` — 관리자 페이지에서 내보낸 질문/답변/덱 설정 (스키마는 §4-1 참조)
- 답변 키: `{arcana}-{번호}` (예: `major-0`, `wands-3`) × `upright`/`reversed`

### AI 연동 확장 (v2 이후)
- 결과 화면 정적 해석 하단에 "AI 심층 해석 보기" 버튼 자리 확보
- 뽑힌 카드 조합 + 카테고리 + 포지션을 컨텍스트로 LLM API 호출하는 구조 — 정적 데이터가 프롬프트 재료로 재사용됨
- 관리자 페이지 "AI로 전체 생성": 질문 텍스트 + 카드별 기본 의미를 컨텍스트로 질문×카드 답변을 일괄 생성, 관리자 검수 후 저장

## 7. 비기능 요구사항

- **성능:** 초기 로드 JS < 150KB(gzip), 카드 이미지 lazy load + WebP, Lighthouse 모바일 90+
- **모바일 우선:** 기준 뷰포트 360px, 터치 타깃 최소 44px, 세로 스크롤 단일 축
- **접근성:** 카드 이미지 alt 텍스트(카드 이름), 애니메이션 `prefers-reduced-motion` 대응
- **아이콘:** Lucide(`lucide-react`) 단일 사용, 이모지 사용 금지 (상세는 DESIGN.md §4 Iconography)
- **오프라인:** 정적 자산 + 데이터 내장으로 네트워크 없이 열람 가능 (PWA는 v2 검토)
