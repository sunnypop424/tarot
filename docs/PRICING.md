# 원가와 가격

**원가는 실측이고, 판매가는 제안이다.** 아래 토큰 수치는 2026-07-16 에 `claude-haiku-4-5` 로 실제 호출해 잰 값이다 (`node scripts/verify-ai.mjs` 가 끝에 같은 계산을 출력한다). 판매가 쪽은 내가 시장을 모른다 — 구조와 가정만 제시하니 숫자는 직접 검증해야 한다.

환율은 1달러 = 1,400원으로 계산했다.

## 1. 실측 원가

Haiku 4.5 단가: **입력 $1 / 출력 $5** (per 1M 토큰).

| 작업 | 입력 | 출력 | 1회 원가 |
|---|---:|---:|---:|
| **3장 리딩 종합** (애정·금전·직업) | 1,529 | 406 | **$0.00356 ≈ 5.0원** |
| **질문 답변 생성** (카드 12장 한 묶음, 정+역) | 6,907 | 2,630 | $0.0201 ≈ 28원 |
| └ 카드 1장당 (정+역 두 답변) | — | — | **$0.00167 ≈ 2.3원** |

입력이 출력보다 큰 이유: 카드마다 `core`(본질) + `symbolism`(그림 묘사)를 프롬프트에 넣는다. 3장이면 그것만 ~1,300 토큰이다.

### 질문 하나를 통째로 생성하면

| 카드 범위 | 답변 수 (정+역) | API 호출 | 1회 생성 |
|---|---:|---:|---:|
| 메이저 22장 | 44개 | 2회 | **$0.037 ≈ 51원** |
| 전체 78장 | 156개 | 7회 | **$0.130 ≈ 183원** |

**재생성을 감안한 현실 값** — 주최자가 마음에 안 들어 다시 돌리는 걸 평균 3회로 잡으면:

| 카드 범위 | 질문 1개 | 질문 5개 | 질문 10개 |
|---|---:|---:|---:|
| 메이저 22장 | 153원 | 765원 | 1,530원 |
| 전체 78장 | 549원 | 2,745원 | 5,490원 |

**세팅 비용은 통째로 만 원을 안 넘는다.** 여기서 아낄 게 없다.

## 2. 이벤트당 AI 원가

리딩은 **3장 스프레드(애정·금전·직업)에서만** 발생한다. 오늘·주간·월간·예/아니오·질문 타로는 전부 1장이라 **AI 를 아예 안 부른다** (원가 0).

### 캐시로 아낄 수 있나 — 거의 못 아낀다

리딩은 `(카테고리 + 카드 + 방향 + 관점)` 키로 캐시한다. "만든 리딩을 DB 에 쌓아두고 같은 조합이면 불러오면 한도를 덜 쓰지 않나?" 는 자연스러운 생각인데, **조합이 너무 많다.** 메이저 22장 3장이면 22×21×20 순열 × 정/역 2³ = **73,920 가지**다.

같은 조합이 두 번 나올 확률(생일 문제)로 계산한 실제 절감:

| 상황 | 조합 수 | 리딩 | 캐시 히트 | 아끼는 돈 |
|---|---:|---:|---:|---:|
| 메이저 22장 · 리딩 1,500회 | 73,920 | 1,500 | 15회 (1.0%) | 76원 |
| 메이저 22장 · 리딩 6,000회 | 73,920 | 6,000 | 237회 (4.0%) | 1,185원 |
| 전체 78장 · 리딩 6,000회 | 3,651,648 | 6,000 | 5회 (0.1%) | 25원 |

**영구 캐시를 붙여도 1~4% 밖에 안 준다.** 그러니 캐시를 DB 로 옮기는 건 **원가 때문이 아니라** 다른 이유로 한다: 서버가 재시작해도 남고, 같은 방문자가 새로고침했을 때 같은 리딩이 나온다(일관성). 그건 그것대로 필요하지만 예산 대책은 아니다.

> 예외: 주최자가 **펼치는 카드 수를 줄이면** 조합이 급격히 줄어 캐시가 먹힌다 (10장 → 12% 절감, 5장 → 69%). 하지만 펼침 수를 줄이는 건 "내가 고른 카드"라는 리추얼을 깎는 일이라 돈 아끼자고 할 짓은 아니다.

**예산을 지키는 건 캐시가 아니라 한도다** (§5 · `src/data/plans.ts`). 아래는 전부 캐시 0% 가정이다.

| 방문자 | 1인당 3장 리딩 | 리딩 횟수 | AI 원가 |
|---:|---:|---:|---:|
| 100명 | 2회 | 200 | **1,000원** |
| 300명 | 2회 | 600 | **3,000원** |
| 500명 | 3회 | 1,500 | **7,500원** |
| 1,000명 | 3회 | 3,000 | **15,000원** |
| 3,000명 | 3회 | 9,000 | **45,000원** |

세팅(질문 답변 생성)까지 더해도 **큰 이벤트가 5만 원대**다.

## 4. 그래서 얼마에 파나

원가가 이벤트당 수천 원이라 **원가 기반 가격은 의미가 없다.** 이 서비스가 파는 건 토큰이 아니라 *팬이 카페에서 QR 찍고 30초 안에 카드를 뽑는 경험*이다 — 가격은 가치 기반이어야 한다.

> ⚠️ **아래 판매가는 내가 지어낸 숫자다.** 생일카페 대관비·굿즈 제작비 상당액을 참고했지만 실제 시세를 확인하지 않았다. **주최자 두세 명에게 물어보고 고쳐야 한다.** 확실한 건 원가(1~3절)뿐이다.

### 제안 — 기간 × 규모 차등

| | **무료** | **라이트** | **스탠다드** | **프리미엄** |
|---|---|---|---|---|
| 기간 | 체험 | 3일 | 7일 | 14일 |
| 방문자 | — | ~300명 | ~1,000명 | ~2,000명 |
| 카드 범위 | 메이저 22장 | 메이저 22장 | 전체 78장 | 전체 78장 |
| 질문 타로 | 3개 | 3개 | 10개 | 무제한 |
| **3장 리딩 (AI 종합)** | ✗ | ✗ | ✓ 1,500회 | ✓ 6,000회 |
| **질문 답변 AI 생성** | ✗ 직접 입력 | ✓ 15회 | ✓ 50회 | ✓ 150회 |
| 카드 앞면 이미지 | 기본(텍스트) | 기본(텍스트) | 22장 커스텀 | 78장 커스텀 |
| 로고·색 커스텀 | ✓ | ✓ | ✓ | ✓ |
| 수정구슬 커스텀 | — | — | ✓ | ✓ |
| **가격** | **0원** | **12만원** | **30만원** | **60만원** |
| 예상 AI 원가 | 0원 | ~2,700원 | ~16,700원 | ~57,500원 |
| **원가율** | — | 2.3% | 5.6% | 9.6% |

**AI 가 유료의 경계다.** 무료는 AI 를 아예 안 준다 (전부 1장 + 답변 직접 입력). 라이트는 답변 생성만, 3장 AI 종합은 스탠다드부터 — 리딩이 원가의 대부분이라 여기서 값이 갈린다.

**추가 옵션**
- 기간 연장: 3일당 +3만원
- 방문자 초과: 500명당 +2만원 (실제 원가는 1만원 이하 — 여유가 크다)
- 카드 앞면 이미지 제작 대행: 별도 견적 (이건 원가가 AI 가 아니라 **사람 시간**이다)

### 이 구조에서 조심할 것

- **무제한은 두지 않았다.** 방문자 3,000명이 1인당 5회 뽑으면 리딩 15,000회 = 7.5만원이다. 그래서 플랜마다 한도가 있고 서버가 강제한다 (§5). 한도가 모자라면 슬롯별로 올려주면 된다.
- **가격을 규모로 가르는 건 자연스러운데, 실제 원가는 규모를 따라가지 않는다.** 라이트와 프리미엄의 원가 차이는 5만원, 가격 차이는 48만원이다. 이건 정상이다 — 파는 게 토큰이 아니니까. 다만 **주최자에게 "AI 원가 때문에 비싸다"고 설명하면 안 된다.** 들키면 신뢰를 잃는다. 파는 건 세팅·디자인·운영이다.
- **카드 앞면 78장 커스텀이 진짜 원가다.** AI 5만원보다 이미지 78장 만드는 사람 시간이 훨씬 비싸다. 프리미엄 가격의 근거는 여기에 있다.

## 5. 원가가 새지 않게 — 플랜 한도

**플랜이 곧 예산 상한이다** (`src/data/plans.ts` · `src/data/plans.json`). 최고관리자가 슬롯 편집기에서 정하고, **서버가 강제한다** — 화면에서 버튼을 감추는 건 안내지 방어가 아니다(curl 로 부르면 그만).

| 플랜 | 3장 리딩 | 리딩 한도 | 답변 생성 | AI 원가 | 원가율 |
|---|---|---:|---:|---:|---:|
| 무료 | ✗ (전부 1장) | 0 | 0 (직접 입력) | 0원 | — |
| 라이트 12만원 | ✗ (전부 1장) | 0 | 15회 | ~2,700원 | 2.3% |
| 스탠다드 30만원 | ✓ | 1,500 | 50회 | ~16,700원 | 5.6% |
| 프리미엄 60만원 | ✓ | 6,000 | 150회 | ~57,500원 | 9.6% |

- **한도를 넘어도 앱은 안 멈춘다** — AI 종합만 빠지고 카드별 해석으로 돌아간다. 방문자는 "고장"이 아니라 "종합이 없는 화면"을 본다.
- 슬롯마다 `limits` 로 한도를 **더 줄 수 있다** (편집기에서 플랜 값이 기본으로 들어가고, 그 위에서 올린다). 추가 요청을 받았을 때 플랜을 통째로 올리지 않아도 된다.
- 한도의 목적은 이윤 보호가 아니라 **사고 방지**다 — 새로고침 연타, 무한 재생성.

### 아직 없는 것 (Supabase 로 옮길 때 같이)

| 장치 | 지금 | 붙일 때 |
|---|---|---|
| 사용량 카운터 | **프로세스 메모리** — 개발 서버를 재시작하면 0 | DB. 안 그러면 한도가 리셋된다 |
| 리딩 캐시 | 프로세스 메모리 (`Map`) | 테이블 — 원가 절감이 아니라 일관성 때문 (§2) |
| 레이트리밋 | **없음** | IP·세션당 |
| 답변 생성 권한 | 누구나 호출 가능 | 주최자 세션(JWT)만 — 78장 = 183원짜리 버튼이다 |
| 사용량 로깅 | 응답에 `usage` 만 | 슬롯별 누적 → 정산 근거 |

**가장 급한 건 카운터를 DB 로 옮기는 것이다.** 지금은 서버를 재시작하면 한도가 처음으로 돌아간다.

## 6. 계산을 다시 하려면

```
node scripts/verify-ai.mjs
```

끝에 실측 토큰과 원가가 나온다. 모델을 바꾸면(`ANTHROPIC_MODEL=claude-sonnet-5`) 그 값으로 다시 잰다 — Sonnet 5 는 입력 $3 / 출력 $15 라 **원가가 정확히 3배**가 된다 (3장 리딩 15원, 78장 생성 550원). 그래도 이벤트당 15만원이면 원가율은 여전히 낮다.
