# DESIGN — 화면을 만들 때 지킬 것

> **새 서비스를 얹을 때 먼저 읽는다.** 이번 정리는 한 번이지만 규칙은 계속 쓰인다.
>
> 근거와 그때의 판정은 `docs/REVIEW_COMMON.md` 에 있다. 여기는 **결론만** 둔다.
>
> 소스 곳곳이 이 파일을 가리킨다(`components.css`·`tokens.css`·`layout.css`·`StarField.tsx` …).
> **번호가 아니라 절 이름으로 가리킨다** — 번호를 쓰면 절이 하나 늘 때마다 참조가 어긋난다.

---

## 클래스 명명

방문자 화면은 **CSS 모듈**, 주최자 운영도구는 **`ad-*`**(`styles/organizer.css`), 슬롯 편집기는
**`owner-*`**(`styles/admin.css`). 이 셋은 섞지 않는다 — 두 도구가 클래스를 나눠 쓰면 한쪽을
고칠 때 다른 쪽이 같이 움직인다.

모듈에서 `.card`·`.head`·`.empty`·`.backBtn` 을 새로 정의하기 전에 `components.css` 에 있는지
먼저 본다. **공통 파일에 서비스 이름을 박지 않는다.**

## 공통 컴포넌트 사용

버튼·아이콘버튼·표면·칩·빈 상태는 전역 클래스를 `composes: … from global(...)` 로 끌어온다.
**새 치수를 화면에서 만들지 않는다** — 만들어야 한다면 왜 다른지를 파일 머리말에 적는다.

이미 있는 공통 부품은 그대로 쓴다:

| 부품 | 하는 일 |
| --- | --- |
| `components/ServiceHeader` | 로고+제목 한 줄. **로고가 없으면 로고 자리를 안 그린다**(빈 타일은 "그림이 깨졌다"로 읽힌다) |
| `components/AdminEntry` | 화면 구석의 "관리자" 진입. 내부는 `<Link>` — `<a href>` 로 앱을 다시 받지 않는다 |
| `components/Pager` · `usePaged` | 목록 페이지 나누기 |
| `components/SavableImage` | **`<img>` 가 허용되는 유일한 자리** (`npm run verify:noimg` 가 지킨다) |

## 레이아웃

방문자 화면은 모바일 단일 컬럼, 최대 폭 480px 중앙 정렬(`styles/layout.css`).
관리 도구(`.admin`·`.owner`)만 최대 폭 제한이 없다 — 데스크톱 편집 작업이 전제라 데이터
밀도가 높은 배치를 허용한다.

## 토큰

hex·radius·그림자 **리터럴 금지.** `9999px` 은 `var(--radius-full)`.

**서비스 색의 기본값은 `data/serviceTheme.ts` 에서 받는다** — 리터럴 hex 를 기본값으로 두면
최고관리자가 고른 색이 그 서비스에 영영 안 닿는다(실제로 7개 서비스가 그랬다).
고정색이 필요한 자리(카메라 UI, 카드 무대, 어두운 상영관, 밤하늘)는 **그 이유를 파일
머리말에 적는다.** 로컬 변수는 `--<svc>-*` 접두사.

**예외는 둘뿐이고 둘 다 스스로 선언한다:** `styles/admin.css` 와 `styles/organizer.css`.
관리 도구는 어느 슬롯을 열든 같은 색이어야 해서 `:root` 의 슬롯 토큰을 고정값으로 덮는다 —
그 고정값은 각 파일의 **토큰 블록 안에만** 둔다.

## 컴포넌트·아이콘

아이콘은 **Lucide 만** 쓴다 — 이모지 금지(`data/categories.ts`).
장식·카테고리 아이콘은 포인트색(`.icon-accent`), 기능 아이콘은 텍스트 색(`.icon-muted`).
포인트 아이콘은 **파생색**을 쓴다 — raw accent 는 어두운 카드 기준이라 밝은 표면에서 사라진다
(`lib/theme.ts` 의 `DERIVED_COLORS`).

## 장식

미스틱한 장식(별·글로우)은 **정적 SVG·CSS 로만** 만든다 — **파티클 라이브러리 금지**
(`components/StarField.tsx`). 관리 도구에는 장식을 넣지 않는다.

## 모션

전환은 토큰(`--dur-*`·`--ease`)으로만 준다(`styles/tokens.css`).
카드 뒤집기는 CSS `rotateY` 단일 트랜지션(`components/FlipCard.module.css`).

## 접근성

`prefers-reduced-motion` 이 켜져 있으면 전 구간 즉시 전환(`styles/tokens.css`).
터치 타깃은 `--tap-min`(44px) 아래로 내려가지 않는다.

## 예시 이름

**실존 아이돌·그룹 이름을 예시로 쓰지 않는다.** 샘플 슬롯·플레이스홀더·문서·데모 데이터
어디에도 안 쓴다 — 실존 인물이고, 이 레포는 공개될 수 있으며, 그 사람과 무관한 서비스가
그 이름을 달고 도는 꼴이 된다.

정해 둔 가상 이름을 쓴다: 그룹 **스타릿**(멤버 **리안**, 슬러그 `starlit-rian`) ·
그룹 **문셋**(멤버 **하온**, 슬러그 `moonset-haon`). 샘플 팬 닉네임도 사람 이름 대신
방문자 닉네임풍(별하나·노을·파도·첫눈…)으로 둔다 — 흔한 이름을 쓰면 그게 또 누군가와 겹친다.

## 용어

카페에서 페이지를 여는 사람은 **방문자** 하나로 부른다 — 화면·코드·타입·문서·검증
스크립트가 전부 같은 말을 쓴다. 한때 화면만 "손님" 이었는데(그때 판정은 `REVIEW_COMMON.md`
4번), 갈라 두니 랜딩의 "손님 폰" 과 코드의 `visitor` 가 같은 사람을 다르게 불렀다.

**"손님" 을 다시 넣지 않는다.** 넣으면 조사도 같이 갈린다 — 손님은 받침이 있고 방문자는
없어서 이/가·은/는·을/를이 전부 달라진다(바꿀 때 201줄이 깨졌다).

운영 주체는 **주최자 / 최고관리자 / 스태프** — 화면에서 "고객"은 쓰지 않는다.
방문자 화면의 진입 링크만 "관리자"다(누르는 사람이 최고관리자일 수도 있어서).

노출어는 **선물 · 뽑기 · 회**. "보상"·"추첨"·"가챠"는 코드에만 둔다.

서비스 운영 종료는 **마감**, 슬롯 대여 만료는 **종료** — 다른 개념이라 섞지 않는다.

## 화법

**전 화면 해요체.** 확인창은 `~할까요?` 제목 + 짧은 동사형 okLabel + 감정어 없는 사실 진술 desc.
파괴적 동작도 해요체를 유지한다 — 톤을 딱딱하게 바꾸는 대신 결과를 정확히 적는다.

**예외는 랜딩 하나다** (`src/landing/*`, 문의 창과 문의 양식 포함) — 거기만 **합니다체**다.
읽는 사람이 다르다: 앱은 이미 맡긴 사람이 쓰고, **랜딩은 맡길지 정하는 자리**다.
개인이 혼자 받는 커미션이라 그 판단에 필요한 건 친근함보다 신뢰다.
문구 전문은 `docs/랜딩-문구.md` 에 있다.

운세·판정처럼 단정하면 안 되는 자리는 단정하지 않는 화법을 쓴다(`data/yesno.ts`).

**막힌 기능은 왜 막혔는지 반드시 말한다** — 이유 없는 `disabled` 는 버그로 취급한다.

## 건드리지 않을 것

- **조작 주체 경계** — 타로는 방문자가 자기 폰으로, 럭키드로우·포카(판매)는 스태프가 부스
  기기에서. `src/staff/*` 가 관리 셸 **밖**에 있는 이유다.
- **슬롯 격리** — 테마·질문·권한은 slug 스코프.
- **역할 분리** — 슬롯 편집기를 주최자 `/admin` 으로 끌어오지 않는다.
- **`.admin`·`.owner` 의 고정 라이트** — 관리 도구는 어느 슬롯에서 열든 같은 색이다.
- **서비스의 정체성** — 럭키드로우의 스크래치, 타로의 카드 뒤집기, 소원나무의 등불,
  스탬프의 도장 찍히는 손맛. 억지로 묶으면 서비스가 죽는다.
