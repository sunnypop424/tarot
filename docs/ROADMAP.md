# 구현 로드맵

## M1 — 기반 + 오늘의 타로

**완료됨**
- Vite + React + TS 스캐폴드 (`lucide-react`, react-router)
- `docs/cards/*.md` → `src/data/cards.json` 변환 스크립트 (78장 전수 검증 포함)
- CSS 아키텍처: `tokens → reset → base → layout → components` (색은 전부 토큰, 화면별은 CSS 모듈)
- 테마 시스템: `Theme` 스키마 + `applyTheme()` 런타임 주입 + `?theme=<id>` 전환 + 로고/배경패턴/카드이미지 슬롯
- 홈 / 운세 / 질문 3화면 + 탭바 (시안 반영)
- 모바일 뷰포트 스크린샷 검증 도구 (`npm run shot`)

- 카드 앞면(테마 이미지 + 텍스트 폴백) / 뒷면(테마 이미지 + 내장 SVG 폴백)
- 카드 플립(`rotateY`) — 결과 화면에서 스크롤로 드러날 때 뒤집힘
- **뽑기 플로우 전체** — 부채꼴 여러 줄 펼치기(높이 반응 3줄/2줄) → 셔플 연출 → 선택 → 슬롯으로 날아가 얹힘 → X로 다시 고르기 → 결과 + 해석. 6개 카테고리 전부 이 하나로 동작
- 오늘의 타로 하루 1회 (localStorage 날짜 키, 자정 리셋)
- 역방향 30% 로직
- IA 확정: 탭바 홈/운세/질문 3개 + 도감은 헤더 아이콘
- 뽑기 플로우 E2E 검증 도구 (`node scripts/verify-draw.mjs <카테고리> <출력경로> [폭] [높이]`)

## M2 — 기간 운세 + 도감 + 질문 타로

**IA 확정 (탭 2개)**
- **홈** = 기간 운세. 세그먼트 오늘 / 주간 / 월간 — 셋 다 **직접 뽑고 각각 1장**. 뽑는 주기만 다른 같은 것이라 한 화면에 묶었다
- **운세** = 주제별 뽑기(애정·금전·직업·예아니오) + 질문 타로 목록. "궁금할 때 골라 뽑는다"는 같은 성격이라 합쳤다
- 도감은 헤더 아이콘

**완료됨**
- 기간 잠금 (`src/lib/storage.ts`) — 오늘=자정 / 주간=월요일 / 월간=1일에 다시 열린다. 기간 키가 바뀌면 저장분이 자동 무효
- 오늘·주간·월간을 카테고리로 통합 (`period` 필드가 잠금을 건다) — 뽑기 플로우 하나로 전부 동작
- 한 장짜리 기간 운세에 애정·금전·직업 한 줄 요약
- `ReadingCard` / `CardDraw` 공통 컴포넌트 — 카테고리·기간·질문 타로가 같은 손맛과 모양으로 동작
- 카드 도감 (78장 목록 + 수트 필터 + 상세: 상징 + 정/역방향 전체 의미)
- 질문 타로 (`/question/:id`) — 질문별 덱 설정(범위·펼침 수·역방향) 적용, 답변은 관리자 입력 → 카드 의미 폴백
- 검증 도구: `verify-fortune.mjs`(세그먼트·기간 잠금·복원·타이틀 정렬), `verify-pages.mjs`(도감 78장·상세 섹션·질문 타로)

- 예/아니오 판정 (`src/data/yesno.ts`) — 메이저 명시 + 마이너 수트 규칙, 역방향은 답을 뒤집음. 해석 맨 앞에 조언과 같은 디자인으로 노출
- 카테고리 기본 1장 + 관리자가 1/3 선택 가능한 구조 (`spreads` / `defaultCount`)

**남음**
- 3장 스프레드의 **종합 해석** — 정적 데이터로는 억지스러워 AI 연동(M4)에서 해결한다. 그전까지 3장은 각 장을 짧게만 보여준다

## M3 — 슬롯 구조 + 관리자 + 테마 편집기

**완료됨**

*슬롯 (멀티테넌트)* — 배포 하나에 여러 이벤트
- `/{slug}` 가 각 이벤트의 루트. 배포 루트(`/`)는 아무것도 노출하지 않는다 (슬롯 목록 = 남의 이벤트)
- 슬롯마다 테마·이벤트 설정·질문이 **전부 격리**된다. `src/lib/repo/` 의 모든 메서드가 slug 를 받는다
- `src/data/slots.json` (소유자 배포) · `SlotProvider` · `useSlotPath()` (모든 내부 링크가 슬롯 안에 머문다)

*주최자 관리자* — `/{slug}/admin`
- 이메일+비밀번호 로그인 (UI만 — 인증 판정은 `repo.auth` 어댑터 몫, 화면에 미구현임을 명시)
- 슬롯 스코프 가드: 다른 슬롯 계정이면 로그인으로 되돌린다
- 질문 CRUD + 공개 토글, 질문별 덱 설정, 카드별 정/역 답변 (미입력 = "폴백 사용 중" 표시)
- 편집 즉시 저장 (저장 버튼 없음)

*소유자 테마 편집기* — `/theme-editor`, **개발 모드 전용**
- 라이트 UI (편집 중인 이벤트 색과 섞이지 않게 고정)
- 색 17개 + radius 3개 + 이벤트 설정 (카테고리 1/3장)
- **파일 업로드** — Vite 개발 서버 미들웨어가 `public/slots/{slug}/` 에 실제 파일로 저장한다. 카드 앞면은 최대 78장, 파일명이 카드 id 면 한 번에 올릴 수 있다. 그 폴더를 커밋하면 배포
- 라이브 미리보기 — 편집분을 localStorage 에 저장하고 iframe 이 `storage` 이벤트로 받아 즉시 반영
- WCAG 대비 검사 (본문 4.5:1 / 큰 글자 3:1)
- `slots.json` 내보내기/가져오기

*그 외*
- `Theme` 에 `shape`(radius) 추가 — 슬롯마다 인상이 달라진다
- **밝은 배경 대응** — `applyTheme()` 이 캔버스 휘도로 그림자·딤 세기와 `color-scheme` 을 자동 전환
- 질문이 원격 데이터가 됨 (`QuestionsProvider`) — 실패 시 번들된 `questions.json` 으로 폴백
- 이벤트 설정이 실제 뽑기에 연결됨 (`Draw.tsx` → `CardDraw`)
- 검증: `verify-admin.mjs`(슬롯 격리·CRUD·반응형), `verify-owner.mjs`(라이트·업로드·경로조작 차단·미리보기·밝은 배경)

**남음**
- **백엔드 연동 (Supabase/Firebase 미정)** — 지금은 localStorage 어댑터라 주최자가 고친 답변이 방문자에게 가지 않는다. `src/lib/repo/index.ts` 한 줄 교체로 붙는다
- 실제 인증 (가드는 배선됨, 판정만 어댑터에)

## M4 — 확장 (v2)
- 히스토리 (localStorage, 최근 30개)
- 결과 공유 (Web Share API / 이미지 캡처)
- AI 심층 해석 (LLM API 연동 — 정적 의미 데이터를 프롬프트 컨텍스트로 재사용)
- 관리자 "AI로 전체 생성" 활성화 (질문×카드 답변 일괄 생성 + 검수 플로우)
- (선택) Supabase 등 경량 백엔드 — 질문/답변 실시간 반영 (재배포 불필요)
- PWA (홈 화면 추가, 오프라인 캐시)
- 켈틱 크로스 등 심화 스프레드

## 카드 이미지 소싱 방침 (M1에서 결정)
- **1안:** Rider-Waite 원본 스캔 — 1909년작 퍼블릭 도메인, 무료 사용 가능. 단 파일 용량 최적화(WebP, ~30KB/장) 필수
- **2안:** CSS/SVG 미니멀 자체 디자인 — 골드 라인 심볼 + 카드명. 용량 최소·무드 통일이 장점, 제작 공수 필요
- 권장: 1안으로 시작(즉시 78장 확보), 2안은 브랜딩 강화 시 교체

## 품질 게이트
- 초기 로드 JS < 150KB (gzip), Lighthouse 모바일 90+
- 78장 데이터 전수 검증 스크립트 통과 (필드 누락 0)
- `prefers-reduced-motion` 동작 확인
