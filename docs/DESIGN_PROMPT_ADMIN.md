# 주최자 화면 디자인 프롬프트 — **무엇이 필요한가만**

> 배치도·컴포넌트 지시는 일부러 넣지 않았다. **어떤 화면에 어떤 항목과 동작이 있어야 하는지**만
> 적는다. 구성·위계·형태는 디자인 쪽에서 정해 주면 된다.
> 아래 "지켜야 하는 것" 세 가지만 제약이고, 나머지는 전부 열려 있다.

---

## 0. 쓰는 사람과 상황

- **아이돌 생일카페 이벤트의 주최자와 현장 스태프**가 쓰는 운영 도구다. 방문자는 못 본다.
- 준비는 노트북에서, 당일 운영은 폰·태블릿에서 한다. 두 폭 다 실제로 쓰인다.
- 카운터에 세워둔 기기에 종일 떠 있기도 하다 — 손님이 옆에서 볼 수 있다.
- 하루짜리 행사 중에 급히 누른다. 처음 쓰는 사람이 설명 없이 알아볼 수 있어야 한다.
- 서비스(타로·럭키드로우·포토카드·롤링페이퍼·소원나무·포토존·영상회·투표·스탬프·모의고사)마다
  메뉴 구성이 다르다. **한 슬롯은 서비스 하나만** 쓴다.

## 1. 지켜야 하는 것 (이 셋만 제약)

1. **행사 테마 색을 따르지 않는다.** 어느 행사를 열든 같은 도구로 보여야 한다.
2. **손님 개인정보를 상시 노출하는 화면을 만들지 않는다.** 이름·연락처는 따로 들어가는 화면에서만.
3. **되돌릴 수 없는 동작**(교환권 수령 처리, 추첨, 삭제, 계정 빼기)은 실수로 눌리지 않아야 하고,
   누른 결과가 무엇이었는지 화면에 남아야 한다.

## 2. 모든 화면에 공통으로 있는 것

- 지금 보고 있는 **행사 이름과 주소(슬러그)**
- **메뉴** — 서비스마다 4~10개. 성격이 다른 묶음이 섞인다(현황 / 그 서비스의 운영 / 보상 / 계정 / 방문자 페이지 열기)
- 화면 이름과 **그 화면의 현재 숫자**(예: 공개 3문항 · 만점 30점 / 응모자 128명 · 남은 후보 96명)
- 로그인한 계정, 로그아웃
- (가끔) 최고관리자가 대신 보고 있다는 알림

## 3. 화면별로 필요한 항목

### 대시보드
- 오늘의 숫자 3~4개 (서비스마다 다름: 뽑힌 수 · 남은 재고 · 발급된 교환권 · 참여자 수 …)
- 행사 기간 상태 (시작 전 / 진행 중 · 남은 일수 / 종료 · 자료 보관 남은 기간)
- 자주 가는 화면으로 가는 길
- 재고가 있는 서비스면 **품목별 소진 정도**
- 행사 자료를 통째로 내려받는 동작

### 문항·카드·설문 같은 **목록 화면**
- 항목마다: 순서, 이름 또는 내용, 그 항목의 속성 몇 가지(유형·배점·레어도·보기 수·재고…)
- 항목마다의 동작: 공개/비공개 바꾸기, 고치기, 지우기
- **경고해야 하는 상태**: 정답이 비었다 / 재고가 0이다 / 비공개다 — 목록에서 바로 보여야 한다
- 어떤 목록은 **행 안에서 바로 값을 바꾼다**: 레어도 고르기, 재고 숫자 넣기, 현장 암호 넣기·새로 만들기
- 새 항목 추가
- 목록 전체에 적용되는 규칙 설명 (예: 재고를 비우면 무제한, 레어도가 곧 확률)
- 항목이 하나도 없을 때 무엇을 하면 되는지

### 표로 보는 화면 (발급된 교환권, 응모자 명단)
- 검색 (코드·내용·닉네임으로 찾기) 과 몇 건 중 몇 건인지
- 줄마다: 코드, 내용, 상태(수령 여부·당첨 여부), 시각 몇 개
- CSV 로 내려받기
- 개인정보가 든 명단이면 **보관 기간과 파기 안내**
- 방금 처리한 줄을 알아볼 수 있을 것

### 교환권 수령 확인 (현장에서 제일 많이 쓴다)
- 발급 / 수령 완료 / 아직 안 받음 숫자
- **코드 입력과 처리** — 손님 폰에 뜬 코드를 스태프가 손으로 친다
- 처리 결과 네 가지가 서로 확실히 구별될 것: 처리했음 / 이미 수령함(언제 처리됐는지) / 없는 코드 / 오류
- 입력 보정 안내 (소문자·하이픈·공백은 알아서 맞춰짐), 한 번 처리하면 다시 못 쓴다는 사실
- 발급 목록 (위 표)

### 추첨
- 응모자 · 남은 후보 · 당첨자 수
- 뽑을 인원, 방식(무작위 / 점수순 — 점수가 있는 서비스에서만)
- 추첨 실행
- 방금 뽑힌 사람 목록과 **트위터에 올릴 텍스트 복사** (이 화면에서 제일 많이 눌린다), CSV
- 지난 회차들 — 회차마다 인원·명단, 복사, **그 회차만 되돌리기**
- 후보가 없을 때·점수순 동점 처리 같은 조건 안내

### 스태프 계정
- 계정을 나눠 써야 하는 이유
- 이메일로 계정 만들기
- 만든 직후의 **임시 비밀번호** — 다시 못 본다는 사실, 복사
- 계정 목록: 이메일, 시작일, 본인 표시, 비밀번호 재발급, 빼기
- 본인은 스스로 뺄 수 없다

### 내 계정 (비밀번호 변경)
- 어떤 슬롯의 어떤 계정인지
- 새 비밀번호 · 확인
- 조건 미달·불일치·실패 알림, 성공 알림
- 임시 비밀번호를 그대로 쓰고 있으면 지금 바꾸라는 권유

### 운영 설정 (스탬프·모의고사·포토카드 등)
- 서비스마다 6~10개의 설정값 — 대부분 몇 개 중 고르기, 일부는 숫자·문구
- 값에 따라 **딸려 나오는 하위 설정** (응모로 정하면 "응모 때 받을 정보" 가 열린다)
- 값마다 짧은 설명 — 처음 보는 사람이 뭘 고를지 알 수 있게
- 고를 수 없는 조합은 이유를 말한다 (예: 보상이 있으면 다시 풀기를 못 켠다)
- 저장 버튼 없이 **바꾸면 바로 저장**된다는 것을 알 수 있을 것

### 영상회 상영 설정
- 한 화면에 띄울 말풍선 수, 교체 간격, 1인 입력 수, 글자 수 — 범위 안에서 조절
- 영상 비율, 이름 표시 여부, 마감
- **값마다 권장 범위 안내** ("6~8개가 가장 보기 좋아요")
- 상영 화면(오버레이·엔딩크레딧) 열기
- 상영 중에 바꿔도 그 자리에서 반영된다는 사실

### QR 만들기
- 어떤 주소의 QR 인지 고르기 (손님용 / 스태프·관리용)
- 인쇄 크기 고르기
- 주소 자체와 복사
- QR 미리보기, PNG 내려받기
- 인쇄 전 확인 요령 (폰으로 한 번 찍어 보기, 최소 크기)

### 검수 (쪽지·소원·한마디)
- 남긴 글, 닉네임, 시각
- 숨기기 / 다시 보이기, 지우기
- 숨겨진 것을 알아볼 수 있을 것
- 전체·숨김 개수

### 크게 띄우는 현황 (투표)
- 부스에 세워두는 화면. **조작 버튼 없음**
- 항목별 득표와 비율, 총 표수
- 멀리서 읽힌다

## 4. 어느 화면이든 그려 주셔야 하는 상태

- 아직 아무것도 없을 때 (무엇을 하면 여기 쌓이는지)
- 불러오는 중
- 실패했을 때
- 되돌릴 수 없는 동작을 누르기 직전의 확인
- 폰에서 봤을 때 (가로로 밀리지 않아야 한다)
