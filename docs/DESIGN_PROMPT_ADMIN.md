# 주최자 화면 디자인 프롬프트 — **무엇이 필요한가만**

> 배치도·컴포넌트 지시는 일부러 넣지 않았다. **어떤 화면에 어떤 항목과 동작이 있어야 하는지**만
> 적는다. 구성·위계·형태는 디자인 쪽에서 정해 주면 된다.
> 아래 "지켜야 하는 것" 세 가지만 제약이고, 나머지는 전부 열려 있다.

---

## 0. 쓰는 사람과 상황

- **아이돌 생일카페 이벤트의 주최자와 현장 스태프**가 쓰는 운영 도구다. 방문자는 못 본다.
- 준비는 노트북에서, 당일 운영은 폰·태블릿에서 한다. 두 폭 다 실제로 쓰인다.
- 카운터에 세워둔 기기에 종일 떠 있기도 하다 — 방문자가 옆에서 볼 수 있다.
- 하루짜리 행사 중에 급히 누른다. 처음 쓰는 사람이 설명 없이 알아볼 수 있어야 한다.
- 서비스(타로·럭키드로우·포토카드·롤링페이퍼·소원나무·포토존·영상회·투표·스탬프·모의고사)마다
  메뉴 구성이 다르다. **한 슬롯은 서비스 하나만** 쓴다.

## 1. 지켜야 하는 것 (이 셋만 제약)

1. **행사 테마 색을 따르지 않는다.** 어느 행사를 열든 같은 도구로 보여야 한다.
2. **방문자 개인정보를 상시 노출하는 화면을 만들지 않는다.** 이름·연락처는 따로 들어가는 화면에서만.
3. **되돌릴 수 없는 동작**(교환권 수령 처리, 추첨, 삭제, 계정 빼기)은 실수로 눌리지 않아야 하고,
   누른 결과가 무엇이었는지 화면에 남아야 한다.

## 2. 모든 화면에 공통으로 있는 것

- 지금 보고 있는 **행사 이름과 주소(슬러그)**
- **메뉴** — 서비스마다 4~10개. 성격이 다른 묶음이 섞인다(현황 / 그 서비스의 운영 / 보상 / 계정 / 방문자 페이지 열기)
- 화면 이름과 **그 화면의 현재 숫자**(예: 공개 3문항 · 만점 30점 / 응모자 128명 · 남은 후보 96명)
- 로그인한 계정, 로그아웃
- (가끔) 최고관리자가 대신 보고 있다는 알림

## 3. 화면별로 필요한 항목

### 대시보드
- 오늘의 숫자 3~4개 (서비스마다 다름: 뽑힌 수 · 남은 재고 · 발급된 교환권 · 참여자 수 …)
- 행사 기간 상태 (시작 전 / 진행 중 · 남은 일수 / 종료 · 자료 보관 남은 기간)
- 자주 가는 화면으로 가는 길
- 재고가 있는 서비스면 **품목별 소진 정도**
- 행사 자료를 통째로 내려받는 동작

### 문항·카드·설문 같은 **목록 화면**
- 항목마다: 순서, 이름 또는 내용, 그 항목의 속성 몇 가지(유형·배점·레어도·보기 수·재고…)
- 항목마다의 동작: 공개/비공개 바꾸기, 고치기, 지우기
- **경고해야 하는 상태**: 정답이 비었다 / 재고가 0이다 / 비공개다 — 목록에서 바로 보여야 한다
- 어떤 목록은 **행 안에서 바로 값을 바꾼다**: 레어도 고르기, 재고 숫자 넣기, 현장 암호 넣기·새로 만들기
- 새 항목 추가
- 목록 전체에 적용되는 규칙 설명 (예: 재고를 비우면 무제한, 레어도가 곧 확률)
- 항목이 하나도 없을 때 무엇을 하면 되는지

### 표로 보는 화면 (발급된 교환권, 응모자 명단)
- 검색 (코드·내용·닉네임으로 찾기) 과 몇 건 중 몇 건인지
- 줄마다: 코드, 내용, 상태(수령 여부·당첨 여부), 시각 몇 개
- CSV 로 내려받기
- 개인정보가 든 명단이면 **보관 기간과 파기 안내**
- 방금 처리한 줄을 알아볼 수 있을 것

### 교환권 수령 확인 (현장에서 제일 많이 쓴다)
- 발급 / 수령 완료 / 아직 안 받음 숫자
- **코드 입력과 처리** — 방문자 폰에 뜬 코드를 스태프가 손으로 친다
- 처리 결과 네 가지가 서로 확실히 구별될 것: 처리했음 / 이미 수령함(언제 처리됐는지) / 없는 코드 / 오류
- 입력 보정 안내 (소문자·하이픈·공백은 알아서 맞춰짐), 한 번 처리하면 다시 못 쓴다는 사실
- 발급 목록 (위 표)

### 추첨
- 응모자 · 남은 후보 · 당첨자 수
- 뽑을 인원, 방식(무작위 / 점수순 — 점수가 있는 서비스에서만)
- 추첨 실행
- 방금 뽑힌 사람 목록과 **트위터에 올릴 텍스트 복사** (이 화면에서 제일 많이 눌린다), CSV
- 지난 회차들 — 회차마다 인원·명단, 복사, **그 회차만 되돌리기**
- 후보가 없을 때·점수순 동점 처리 같은 조건 안내

### 스태프 계정
- 계정을 나눠 써야 하는 이유
- 이메일로 계정 만들기
- 만든 직후의 **임시 비밀번호** — 다시 못 본다는 사실, 복사
- 계정 목록: 이메일, 시작일, 본인 표시, 비밀번호 재발급, 빼기
- 본인은 스스로 뺄 수 없다

### 내 계정 (비밀번호 변경)
- 어떤 슬롯의 어떤 계정인지
- 새 비밀번호 · 확인
- 조건 미달·불일치·실패 알림, 성공 알림
- 임시 비밀번호를 그대로 쓰고 있으면 지금 바꾸라는 권유

### 운영 설정 (스탬프·모의고사·포토카드 등)
- 서비스마다 6~10개의 설정값 — 대부분 몇 개 중 고르기, 일부는 숫자·문구
- 값에 따라 **딸려 나오는 하위 설정** (응모로 정하면 "응모 때 받을 정보" 가 열린다)
- 값마다 짧은 설명 — 처음 보는 사람이 뭘 고를지 알 수 있게
- 고를 수 없는 조합은 이유를 말한다 (예: 보상이 있으면 다시 풀기를 못 켠다)
- 저장 버튼 없이 **바꾸면 바로 저장**된다는 것을 알 수 있을 것
  (**예외는 럭키드로우** — 아래 '상품 · 운영' 은 눌러야 저장된다)

### 럭키드로우 — 상품 · 운영 (한 화면)

재고 표와 운영 설정이 **한 화면에 같이 있다.** 행사 중에 오가는 두 가지라 나누지 않았다.
그래서 이 화면만 **눌러야 저장된다** — 수량 여러 칸을 고치는 도중에 값이 나가면 안 된다.

- 위쪽 숫자 셋: 남은 수량(상품 몇 종인지), 오늘 나간 수량(누적도 함께),
  지금 운영 상태(**리허설 / 실제 운영 / 마감** 중 하나 + 그게 무슨 뜻인지 한 줄)
- **상품 표** — 손이 제일 자주 가는 곳이다
  - 줄마다: 등수, 상품명, 남은 수량, 오늘 나감, 누적, 배송이 필요한 상품인지, 지우기
  - **등수는 줄 순서다** — 지우면 아래가 당겨지며 다시 매겨진다
  - **오늘 나감·누적은 손으로 못 고친다** (뽑힌 기록에서 센 값이다)
  - 남은 수량에 적은 숫자가 곧 뽑을 수 있는 수량이라는 것, 다음 날 물량을 더할 땐
    지금 남은 수량에 **더해서** 적는다는 것을 알 수 있을 것
  - 상품 추가, 그리고 표 아래에 남은 수량·오늘 나감 합계
- **운영 설정** — 셋은 켜고 끄는 것이다
  - **실제 운영**: 꺼져 있으면 리허설이라 뽑아도 재고가 줄지 않는다 (기본값이 리허설이다)
  - **행사 마감**: 켜면 방문자가 더 못 뽑는다. 다시 열 수 있다
  - **설정 잠금**: 상품·수량만 못 고치게 잠근다. 뽑기는 그대로 된다
- **당첨 결과 표시** — 방문자에게 무엇으로 보일지 셋 중 하나: 등수와 상품명 / 등수만 / 상품명만
- **경품 미리보기** — 뽑기 전에 어떤 경품이 있는지 보여줄지, 보여준다면 남은 수량까지 보여줄지
  (미리보기를 끄면 수량 표시는 고를 수 없다). 상품명이 스포일러가 되는 행사면 끄라는 안내
- **묶음 뽑기 제한** — 켜면 상품 표에 열이 하나 늘어 상품마다 **5개 뽑을 때 최대 몇 개**를
  정한다(비우면 제한 없음). 켤 때 **흔한 상품이 덜 나오는 만큼 비싼 상품이 빨리 소진된다**는 경고
- 지금 상태를 알려주는 안내: 잠겨 있으면 잠금을 풀어야 고칠 수 있다,
  리허설이면 행사 전에 실제 운영으로 바꿔야 한다
- 저장: 바꾼 게 없으면 누를 게 없다는 걸 알 수 있을 것 (저장 중 / 저장됨),
  **표가 길어져도 저장에 늘 손이 닿을 것**
- **저장 안 하고 나가려 하면 붙잡는다**
- 되돌리기 어려운 것은 저장 직전에 한 번 더 묻는다 — **실제 운영으로 바꾸기 · 마감 · 상품 지우기**

### 럭키드로우 — 배송 정보

**주최자 화면 중 방문자 개인정보가 나오는 유일한 곳이다.** (§1-2 의 "따로 들어가는 화면" 이 여기다.)

- 몇 건인지, 그리고 **배송이 끝나면 반드시 지우라는 것**
- 이름 · 연락처 · 주소로 찾기, 몇 건 중 몇 건인지
- 줄마다: 이름, 연락처, 주소, 당첨 상품(등수·이름·개수), 제출 시각
- CSV 로 내려받기
- **전체 지우기** — 되돌릴 수 없고 다른 데 사본이 없다(방문자도 자기가 넣은 걸 다시 못 읽는다).
  지우기 전에 내려받았는지 묻는다
- 보관 안내: **마감 +14일까지만 열람할 수 있고, +15일이 지나면 저절로 지워진다**
- 아직 아무도 안 냈을 때

### 영상회 상영 설정
- 한 화면에 띄울 말풍선 수, 교체 간격, 1인 입력 수, 글자 수 — 범위 안에서 조절
- 영상 비율, 이름 표시 여부, 마감
- **값마다 권장 범위 안내** ("6~8개가 가장 보기 좋아요")
- 상영 화면(오버레이·엔딩크레딧) 열기
- 상영 중에 바꿔도 그 자리에서 반영된다는 사실

### QR 만들기
- 어떤 주소의 QR 인지 고르기 (방문자용 / 스태프·관리용)
- 인쇄 크기 고르기
- 주소 자체와 복사
- QR 미리보기, PNG 내려받기
- 인쇄 전 확인 요령 (폰으로 한 번 찍어 보기, 최소 크기)

### 검수 (쪽지·소원·한마디)
- 남긴 글, 닉네임, 시각
- 숨기기 / 다시 보이기, 지우기
- 숨겨진 것을 알아볼 수 있을 것
- 전체·숨김 개수

### 크게 띄우는 현황 (투표)
- 부스에 세워두는 화면. **조작 버튼 없음**
- 항목별 득표와 비율, 총 표수
- 멀리서 읽힌다

## 4. 어느 화면이든 그려 주셔야 하는 상태

- 아직 아무것도 없을 때 (무엇을 하면 여기 쌓이는지)
- 불러오는 중
- 실패했을 때
- 되돌릴 수 없는 동작을 누르기 직전의 확인
- 폰에서 봤을 때 (가로로 밀리지 않아야 한다)

## 5. 실제 화면 전부 (하나씩)

> §3 은 화면의 **종류**를 묶어 적은 것이고, 여기는 **존재하는 화면 전부**를 하나씩 적는다.
> **한 슬롯은 서비스 하나만** 쓴다 — 그 주최자가 보는 건 [어느 슬롯에나 있는 화면] +
> [자기 서비스 화면]뿐이다. 다른 서비스 메뉴는 아예 없다.

### 5-0. 관리 셸 (모든 화면을 감싼다)

- 행사 이름과 `/{슬러그} · 관리`
- 계정이 행사를 여럿 갖고 있으면 **행사 바꾸기** (하나뿐이면 아무것도 안 그린다)
- **묶음 제목이 붙은 메뉴** — `현황` / 그 서비스 이름 / (있으면) `보상` / `계정`.
  묶음 제목이 곧 이 슬롯이 파는 서비스라, 행사를 바꾸면 여기가 바뀐다
- 어떤 메뉴는 **관리 셸 밖 화면**이라 새 탭으로 열린다 — 그렇게 열린다는 걸 알 수 있을 것
  (포토카드 스태프 화면, 영상회 오버레이·엔딩크레딧)
- 맨 아래: 로그인한 이메일, 로그아웃 (누르면 바로 로그인 화면으로)
- 노트북 폭과 폰 폭이 둘 다 실제로 쓰인다 — 폰에서 메뉴가 어떻게 되는지도 그려야 한다

### 5-1. 어느 슬롯에나 있는 화면 (5개)

**① 로그인**
- 행사 이름 + `/{슬러그} 관리자`
- 이메일 · 비밀번호 · 로그인
- **왜 안 되는지 구분해서** 말한다: 이메일/비밀번호가 틀림 / 이 행사의 관리자 계정이 아님 /
  아직 확인되지 않은 계정 / 잠시 후 다시
- (백엔드 없는 시험용 빌드면) 아무 값이나 통과하고 **고친 게 방문자에게 안 간다**는 경고

**② 대시보드 — "오늘 현황"** (로그인하면 제일 먼저 열린다)
- 서비스 이름 · 주소, 그리고 **행사 기간 한 줄**: 시작 전 / 진행 중(기간) / 종료까지 N일(마지막
  사흘은 날짜 대신 남은 날) / 기간이 끝났어요 / 기간 제한 없음
- **오늘의 숫자 2~4개** — 서비스마다 다르다:
  - 타로: 질문 수 · 공개 수
  - 럭키드로우: 오늘 나간 경품(리허설분 제외) · 전체 나간 경품 · 남은 재고(상품 종수)
  - 롤링페이퍼 · 소원나무 · 영상회: 남긴 글(숨김 제외) · 오늘 · 숨김
  - 포토존: **없음** — 서버에 쌓이는 기록이 없는 서비스라고 말해 준다
  - 투표: 진행 중 설문 · 받은 표
  - 스탬프: 찍힌 도장 · 판을 채운 사람 · 아직 안 받아간 선물
  - 모의고사: 응시 · 평균 점수 · 나간 교환권 · 아직 안 받아감
  - 포토카드: 나간 카드 · 남은 한정 재고(한정 몇 종·소진 몇 종) · 아직 안 쓴 뽑기권
- 눈에 띄어야 하는 숫자가 있다 (재고가 얼마 안 남음, 안 받아간 선물이 있음)
- **못 읽었을 때 0으로 그리지 않는다** — "지금은 못 봐요" 라고 말한다 (0과 모름은 다르다)
- 재고가 있는 서비스면 **품목별 남은 비율 막대** — 20% 아래와 소진을 구분해서
- **바로 가기** — 그 서비스에서 자주 가는 화면 2~3개 + QR 만들기 + 내 페이지 보기(새 탭)
- **행사 자료 내보내기** — CSV 여러 개로 떨어진다는 것, **개인정보가 든 파일이 섞여 있다**는 것,
  **종료 +14일이 지나면 못 꺼낸다**는 것. 모으는 중 / 내보낼 기록이 없음
- 숫자를 읽어오는 동안의 자리

**③ QR 만들기** (§3 참고 — 실제로 있는 항목)
- 어느 주소: **방문자용** / **스태프·관리용**
- 크기: 작게 / 보통 / 크게(인쇄용)
- 주소 그 자체 + 복사 (복사 실패도 말해 준다)
- QR 미리보기, **PNG 로 저장**
- 안내: 인쇄 전에 폰으로 한 번 찍어 볼 것, 가로 5cm 아래로 줄이지 말 것,
  **방문자용과 관리용을 같이 붙이면 방문자가 관리 화면으로 들어온다**

**④ 스태프 계정** (백엔드가 붙은 배포에서만 — 아니면 그 사실을 말하는 화면)
- 왜 나눠야 하는지 (한 계정을 돌려 쓰면 누가 처리했는지 알 수 없다)
- 이메일 하나로 **계정 만들기**
- 만든 직후의 **임시 비밀번호** — 이 화면을 벗어나면 다시 못 본다는 것, 복사,
  받은 사람은 '내 계정' 에서 바꾸라는 안내
- 이미 있는 계정이면 비밀번호를 안 바꾸고 이 행사에만 연결됐다고 말한다
- 계정 목록: 이메일, 언제부터, **본인 표시**, 비밀번호 재발급(확인), 빼기(확인)
- **본인은 스스로 못 뺀다** — 그 줄에는 빼기가 없다
- 아직 계정이 없을 때

**⑤ 내 계정** (백엔드가 붙은 배포에서만)
- 어떤 행사의 어떤 계정인지, 받은 비밀번호를 그대로 쓰고 있으면 지금 바꾸라는 권유
- 새 비밀번호 · 한 번 더
- 짧음 / 두 값이 다름 / 실패 / 바꿈("다음 로그인부터 새 비밀번호")

### 5-2. 타로 (2개)

메뉴: 현황(대시보드 · QR) / **질문 타로** / 계정

**질문 목록**
- 설명 한 줄: 방문자가 고를 질문과, 카드가 나왔을 때 보여줄 답변을 관리한다
- 숫자 둘: 총 질문 · 공개 질문
- `질문 추가` (누르면 바로 편집 화면으로 간다)
- 줄마다: **공개 체크(누르면 즉시 저장)**, 질문 문구(비었으면 "(제목 없음)"),
  덱(메이저 22장 / 전체 78장)과 **N개 답변 입력됨**, 삭제(확인), 눌러서 편집으로
- 아직 질문이 없을 때 / 불러오는 중

**질문 편집**
- `‹ 질문 목록` 으로 돌아가기
- **자동 저장** 표시(저장 중… / 자동 저장)와 왜 즉시 저장인지 — 저장을 잊어 날리는 게 더 나쁘다
- 질문: 방문자에게 보이는 문구, 공개 체크
- 뽑기 설정: 이 슬롯의 카드 범위는 **여기서 못 바꾼다**는 안내(한 장 뽑고 역방향 50%),
  펼치는 카드 수(최소·최대가 정해져 있고 비우면 전부), 답변을 안 채웠을 때 쓸 관점 5개 중 하나,
  역방향 사용 체크(켜면 답변을 두 배로 써야 한다)
- **카드별 답변** — 카드마다 한 줄(접힘). 줄에 상태 배지: `폴백 사용 중` / `1/2 입력됨`.
  펼치면 정방향·역방향 입력칸, 각 칸에 **비우면 대신 나갈 문장**을 미리 보여준다
- **AI 로 전체 생성** — 플랜에 없으면 버튼 자체가 없고 직접 입력하라고 말한다.
  AI 가 안 붙은 배포면 왜 안 되는지 말한다. 생성 중에는 **몇 장째인지** 보인다
- **검수 줄** (생성 직후, 저장 전): N장 생성됨 · **이미 쓴 답변 N장이 덮어써진다**는 경고 ·
  버리기 / 저장. 검수 중인 카드 줄은 구별되고, **그 자리에서 고칠 수 있다**
- 값이 잘못됐을 때의 알림

### 5-3. 럭키드로우 (2개)

메뉴: 현황(대시보드 · QR) / **상품 · 운영** · **배송 정보** / 계정
→ 두 화면 모두 §3 에 적어 두었다.

### 5-4. 롤링페이퍼 · 소원나무 (1개)

메뉴: 현황 / **롤링페이퍼**(또는 **소원나무**) / 계정
**같은 화면 하나**를 두 서비스가 쓴다 — 부르는 말만 갈아 끼운다(쪽지/소원, 벽/나무).

**검수**
- 전체 개수 · 숨김 개수, 그리고 **남긴 즉시 벽(나무)에 보인다 · 부적절한 것만 숨기거나 지운다**
- 줄마다: 쪽지 종이색, 내용, 닉네임(없으면 익명), 시각, 숨긴 것은 **숨김 표시**
- 숨기기 / 다시 보이기 (누르면 바로 방문자 화면에 반영)
- 지우기 — 확인할 때 **"숨기기만 해도 방문자에겐 안 보인다"** 를 같이 말한다
- 아직 아무도 안 남겼을 때

### 5-5. 포토존 (1개)

메뉴: 현황 / **포토존** / 계정

**안내 한 장** — 만질 데이터가 하나도 없는 서비스다
- 프레임 개수, 따로 설정할 게 없다는 것
- 제일 중요한 문장: **방문자 사진은 방문자 폰에서 합성되고 서버에 저장되지 않는다**
  (그래서 주최자가 보거나 지울 사진도 없다 — 얼굴 사진이라 방문자가 실제로 묻는다)
- 프레임을 바꾸려면 담당자에게 말하면 된다는 것
- 내 페이지 보기

### 5-6. 투표 (2개)

메뉴: 현황 / **설문** · **스크린** / 계정

**설문 관리**
- 개수 + 공개하면 방문자 화면에 바로 나오고 표는 실시간으로 쌓인다는 것
- `설문 추가` — **새 설문은 숨김으로 시작한다** (빈 설문이 방문자에게 보이면 안 된다)
- 설문마다: 제목, **공개 / 준비 중**, **진행 중 / 마감됨**, 지우기(확인 — 받은 표도 사라진다)
- 고르는 방식: 하나만 / 여러 개(여러 개면 최대 개수)
- 선택지 목록: 문구, **그 선택지가 받은 표**, 지우기 / 선택지 추가 / 지금까지 총 몇 표
- **저장하기 + 되돌리기** — 고친 게 있을 때만 (여러 줄 고치는 동안 방문자가 중간 상태를 보면 안 된다)
- **표가 있는 선택지를 지우면 그 표도 사라진다**는 경고
- 아직 설문이 없을 때 / 이 배포에서는 못 쓴다는 안내

**스크린** — §3 '크게 띄우는 현황'. 부스에 세워두는 화면이라 **조작 버튼이 없고**,
관리 도구 색이 아니라 멀리서 읽히는 화면이다.
- 행사 이름 · 설문 제목 · 실시간 표시 · (설정에 따라) 총 표수
- **상위 5개만** — 순위, 항목, 비율, 막대
- 설문이 여럿이면 **가만 둬도 넘어간다**(12초) + 몇 번째인지 점으로
- 공개된 설문이 없을 때

### 5-7. 스탬프 (1개 + 보상 3개)

메뉴: 현황 / **스탬프** / 보상(수령 확인 · 응모자 · 추첨) / 계정

**스탬프**
- 칸 개수 + 각 칸의 암호를 현장에 붙여두면 방문자가 그걸 입력해 도장을 찍는다는 설명
- **현장 암호 목록** — 칸 이름, 암호(기본은 가려져 있고 보기/가리기), 직접 고치기,
  **새로 만들기**(바꾸면 예전 암호는 바로 안 먹는다)
- 운영 설정 — 고르면 바로 저장된다
  - 다 모으면: 보상 없음(축하 화면만) / 확정 선물(교환권 발급) / 응모(나중에 추첨)
  - 선물 이름 (보상이 없으면 못 고침)
  - 날짜별 참여: 한 번만(계속 모음) / 매일 새로(자정 초기화) — 어느 쪽이 어떤 행사에 맞는지
  - 마감: 진행 중 / 마감(도장을 못 찍음)
- 응모로 정하면 **딸려 나오는 하위 설정** — 응모 때 받을 정보(트위터·연락처·주소).
  **안 켠 항목은 아예 안 받는다**, 닉네임은 항상 받는다
- 칸이 아직 없을 때(칸 구성은 담당자가 정한다) / 이 배포에서는 못 쓴다는 안내

### 5-8. 모의고사 (3개 + 보상 3개)

메뉴: 현황 / **모의고사** · **통계** / 보상(수령 확인 · 응모자 · 추첨) / 계정

**문항 목록**
- 공개 N문항 · 만점 N점 · 전체 N문항, `문항 추가`
- 줄마다: 번호, 문제, 유형(객관식/주관식), 배점, 보기 수, 정답 수,
  **정답이 비었으면 "아무도 못 맞혀요"**, 비공개 표시
- 공개/비공개 전환 — **정답이 비면 공개할 수 없고**, 왜 안 되는지 말한다
- 고치기, 지우기(확인 — 이미 응시한 분들의 점수는 그대로 남는다)
- 운영 설정 (고르면 바로 저장):
  보상(없음 / 기준 점수 이상 확정 선물 / 응모) · 기준 점수(지금 만점을 함께 안내) ·
  선물 이름 · 제한시간(없음·3·5·10분) · 정답 공개(틀린 문제만 / 다 보여줌 / 안 보여줌 —
  앞사람이 알려주는 게 걱정되면 안 보여주라는 설명) · 다시 풀기 · 마감
- **고를 수 없는 조합은 이유를 말한다**: 보상이 있으면 다시 풀기를 못 켠다
  (될 때까지 풀면 모두가 당첨된다)
- 응모면 '응모 때 받을 정보' 가 딸려 나온다 (스탬프와 같음)
- 아직 문항이 없을 때

**문항 편집**
- **정답은 방문자 화면에 한 번도 내려가지 않는다 · 채점은 서버가 한다**
- 문제, 유형, 배점, 사진(선택)
- 객관식: 보기 목록 + **정답 하나 고르기**, 보기 추가·삭제
  (정답으로 고른 보기 주변을 지우면 정답을 다시 고르게 된다)
- 주관식: **인정할 답을 여러 개** 담기(칩으로 쌓고 하나씩 뺀다),
  띄어쓰기·문장부호·대소문자는 채점에서 무시된다는 것, 방문자가 다르게 쓸 표현을 미리 넣으면
  문의가 준다는 것
- 방문자에게 공개 체크, 저장하기 / 취소, **저장할 수 없으면 무엇이 비었는지** 말한다

**통계**
- 응시 · 평균(백분율) · 가장 어려운 문항
- 문항마다 정답률(막대)과 맞힌 사람 / 응시한 사람
- **다시 채점** — 인정할 답을 더한 뒤 누르면 **이미 응시한 분들의 점수도 같이 고쳐진다**
  (정답률이 낮은 주관식은 표현 차이일 때가 많다는 설명)
- 아직 문항·응시가 없을 때

### 5-9. 포토카드 (2개, + 셸 밖 1개)

메뉴: 현황 / **카드** · **뽑기권** · 스태프 화면(새 탭) / 계정

**카드**
- 카드 종수 · 남은 수량(또는 무제한)
- **연습 모드가 켜져 있으면 경고** — 지금 뽑아도 재고가 안 줄고, 행사 전에 꺼야 한다
- 카드마다 한 줄: 썸네일, 이름, `럭키` 표시, `소진` 표시, 뽑힌 수, 남은 수량
- **줄 안에서 바로 바꾼다**: 레어도 고르기, 럭키 체크, 재고 숫자
- 목록 전체에 걸리는 규칙 설명: 재고를 비우면 무제한 / 0이면 그 카드는 안 나옴 /
  **레어도가 곧 확률** / 재고는 "나올지 말지" 만 정하고 확률은 안 건드림 /
  **럭키는 표시일 뿐 확률이 아님**
- 운영 설정 (고르면 바로 저장):
  - 운영 방식 3가지(저장용 / 1장 증정 / 판매) — **바꾸면 방문자 화면이 통째로 달라지므로 확인**,
    행사 중에는 바꾸지 말라는 것
  - 방식에 따라 **나타나는 설정이 다르다**: 한 사람이 뽑는 횟수 · 한 번에 최대 ·
    이미지 저장 여부 · 묶음 상한(같은 카드가 몰리는 걸 막는다)
  - 연습 모드, 마감
- 카드가 아직 없을 때 — **이미지 등록은 담당자가 한다**(원본을 보내면 된다)

**뽑기권**
- 발급 · 뽑음 · 대기 수, 스태프 화면 열기(새 탭), CSV
- **발급 수가 방문자 수보다 훨씬 많으면** 브라우저 기록을 지우고 다시 받은 경우라는 설명
- 검색(번호 · 카드 이름)과 몇 건 중 몇 건
- 줄마다: 번호, 뽑았으면 카드 썸네일·이름·레어도·발급/뽑은 시각, 아직이면 `아직 안 뽑음`
- 번호 지우기 — 확인할 때 **이미 뽑은 번호면 그 방문자가 한 번 더 뽑게 된다**는 것을 말한다
- 이 운영 방식에서는 뽑기권을 안 쓴다는 안내 / 아직 발급이 없을 때

**스태프 화면** — 관리 셸 밖(새 탭). 부스 기기에 띄우고 방문자가 같이 보는 화면이라
관리 도구가 아니라 **행사 색**을 쓴다. (별도 프롬프트)

### 5-10. 영상회 응원 (2개, + 셸 밖 2개)

메뉴: 현황 / **상영 설정** · **한마디** · 오버레이(새 탭) / 계정

**상영 설정** — §3 '영상회 상영 설정'. 실제로 있는 것:
- 한 화면에 몇 개 · 교체 간격 · 1인 입력 수 · 글자 수 (범위 안에서 조절 + **값마다 권장 안내**)
- 영상 비율, 이름 표시, 마감(이미 받은 한마디는 그대로 상영되고 새로 받는 것만 막힌다)
- **오버레이 열기 · 엔딩크레딧 열기**(새 탭)
- **오버레이는 배경이 투명하다** — OBS·프리즘의 브라우저 소스로 얹거나 전체화면으로 겹친다
- **상영 중에 바꿔도 그 자리에서 반영된다**
- 검수는 '한마디' 메뉴에서 한다는 안내
- 고치면 바로 저장

**한마디** — 5-4 의 검수 화면과 같은 화면이다.

### 5-11. 공용 보상 화면 3개 (스탬프 · 모의고사가 함께 쓴다)

**보상을 안 쓰는 설정이어도 메뉴에서 사라지지 않는다** — 설정을 바꿔도 이미 나간 코드와
응모는 남기 때문이다. 대신 **각 화면이 자기 상황을 스스로 설명한다**.

- **수령 확인** — §3 '교환권 수령 확인'. 발급/수령 완료/아직 안 받음, 코드 입력과 처리,
  네 가지 결과(처리했음 · 이미 수령함+언제 · 없는 코드 · 오류), 입력 보정 안내,
  발급 목록(검색 · CSV · 방금 처리한 줄 강조)과 **여기엔 방문자 이름을 안 올리는 이유**
  (카운터 화면은 계속 켜져 있다)
- **응모자** — §3 '표로 보는 화면'. 응모 완료 / 자격을 얻은 분 / 아직 안 낸 분,
  **자격만 얻고 응모 안 한 사람은 추첨 후보에 못 들어간다**는 안내, 검색, CSV,
  연락처·주소가 들어 있으면 **다 보내고 지우라는 경고**(+14일이면 잠기고 슬롯을 지우면 삭제),
  받은 항목만 열로 나온다, 비었을 때 **응모를 안 받는 건지 아직 아무도 안 낸 건지 구분**
- **추첨** — §3 '추첨'. 응모자·남은 후보·당첨자, 뽑을 인원·방식(점수가 있는 서비스만),
  추첨(확인), 방금 뽑힌 명단 + **트위터용 복사**(이 화면에서 제일 많이 눌린다)·CSV,
  지난 회차별 명단·복사·**그 회차만 되돌리기**(확인), 후보가 없을 때,
  점수순일 때 동점 처리 설명
