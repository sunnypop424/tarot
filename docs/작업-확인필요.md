## 1. 이번에 한 것

### 1-1. 포토카드 스태프 화면을 **럭키드로우와 같은 화면**으로 ✔

> 섞기 빼고, 카드 형태 디자인 빼고, 초입 디자인은 럭드랑 동일하게.
> 당첨결과 화면 제외 뽑는 부분, 전체결과 부분은 럭드랑 디자인 완전히 동일하게.

두 화면이 하는 일이 같습니다 — **스태프가 수량을 정해 뽑고 결과를 손님에게 건넵니다.**
그래서 같은 화면이어야 하고, 같으려면 **CSS 가 한 벌**이어야 합니다.

`src/components/DrawStage.module.css` 를 새로 만들어 무대·박스·상단 밴드·미리보기 버튼·
관리자 링크·결과 머리말/발치·전체 결과 목록·안내 배너를 **두 화면이 같이 씁니다.**
럭드는 `composes` 로 받아가서 화면 코드(JSX)는 한 줄도 안 바뀌었습니다 — 두 화면이 앞으로
따로 놀 수가 없습니다.

- 뽑는 화면: 밴드(포토카드 미리보기) → 수량 고르기 → 뽑기. 럭드와 같습니다.
- 당첨 결과: 럭드와 같은 뼈대(✦ 두근두근 / 당첨 결과 → 아래 '전체 결과 보기' 한 줄).
  **가운데만 다릅니다** — 등수 타일 대신 카드 그림 + 이름 + 등급.
- 전체 결과: 카드 이름 + 장수, 아래 '처음으로'.
- 섞기·덱 뒷면 연출은 뺐습니다.
- **밴드의 배지도 뺐습니다** — 'STAFF' 든 이벤트 이름이든, 부스에서 손님이 같이 보는
  화면이라 붙어 있으면 "직원용" 으로 읽히고 밴드도 두 줄이 됩니다.

### 1-1-b. 포토카드 **카드 뒷면 이미지** ✔

편집기에서 뒷면을 올리면 **덱 · 뽑는 중 · 뽑기권 받기** 세 화면에 다 깔립니다
(뒷면 그림이 있으면 그 위의 아이콘은 안 그립니다 — 겹치면 지저분합니다).
안 올리면 지금처럼 덱 색에서 만든 무늬예요. **타로 뒷면과는 별개 값**입니다 —
카드 비율이 다르고(55:85 vs 63:88) 한 슬롯이 두 서비스를 같이 팔지 않습니다.
뒷면도 `background-image` 라 길게 눌러 저장되지 않습니다.

'뽑는 중' 화면의 **빛은 대각선**으로 지나갑니다 (세로 띠는 빛이 아니라 화면 결함처럼 보였어요).

### 1-2. 포토카드 편집기 설정을 럭드에서 떼왔습니다 ✔

같은 무대를 쓰니 설정도 같아야 합니다. 포토카드 카드에 **박스** 묶음이 생겼습니다 —
상단 여백 · 안쪽 여백 · 테두리(두께·색) · 그림자(색·번짐·내림) · 관리자 링크 색.
편집기 부품 자체를 공용으로 뺐어요(`src/owner/service/BoxFields.tsx`) — 럭드와 포토카드가
같은 칸을 씁니다. 수량 고르기(`PickerFields`)는 지난번에 이미 공용이고요.

배경 사진과 로고는 원래 슬롯 테마가 들고 있어서 따로 안 만들었습니다(럭드도 같습니다).

### 1-3. 이 과정에서 찾은 버그 셋 ✔ 고침

- **뽑기 버튼 둥글기가 '버튼 둥글기' 설정을 안 따랐습니다.** 수량 고르기를 공용
  컴포넌트로 뺄 때 버튼 모서리를 **상자 둥글기에서 파생**시켜 놓아서, 편집기에서
  버튼 둥글기를 바꿔도 스테퍼·프리셋·뽑기 버튼만 안 따라왔습니다. 버튼 그림자도 같이 복원.
- **박스 그림자가 사라져 있었습니다** — 공용 무대로 옮기면서 빠졌습니다(럭드도 해당).
- **긴 카드 이름이 칸을 뚫고 나갔습니다.** 카드 이름은 파일 이름에서 오는데
  `Gemini_Generated_Image_ab12cd` 처럼 띄어쓰기가 없으면 옆 카드 위로 흘렀어요.
  결과는 두 줄까지, 전체 결과 줄은 말줄임표로.

### 1-4. 편집기 미리보기에서 **모든 화면** 보기 ✔

> 다른 서비스들도 미리보기에서 모든 화면을 볼 수 있어야해
> (주최자 페이지 제외, 사용자 화면 스태프 화면은 미리보기 제공을 해야함)

지난 문서에서 남겨둔 항목입니다. 그때는 럭드(뽑기/당첨/전체결과)와 롤페·소원나무(벽/작성)만
고를 수 있었고, 그것도 **두 방식이 따로**였습니다(럭드는 상태를 건네고 롤페는 주소를 바꿈).
나머지는 첫 화면만 보였고요 — **색을 고르는 사람이 결과·보상 화면을 못 보고 배포한다는 뜻**입니다.

이제 서비스마다 화면 목록이 미리보기 위에 한 줄로 뜹니다:

| 서비스 | 고를 수 있는 화면 |
|---|---|
| 포토카드 | 덱 · 뽑는 중 · 결과 · 보관함 · 뽑기권 받기 · 뽑기권(발급 후) · **스태프 화면** |
| 모의고사 | 시작 · 문항 · 채점 중 · 결과 · 교환권 · 응모 완료 |
| 스탬프 | 스탬프판 · 암호 입력 · 교환권 · 응모 완료 |
| 럭키드로우 | 뽑기 · 당첨 · 전체 결과 |
| 롤페 / 소원나무 | 벽(나무) · 작성 화면 |
| 투표 | 투표 목록 · 투표하기 · 결과 |
| 포토존 | 프레임 고르기 (카메라는 권한 때문에 미리보기에서 안 열립니다) |

**미리보기에서는 진짜로 뽑거나 제출할 수 없습니다** — 재고가 줄고 응모가 쌓이니까요.
그래서 데이터가 없으면 표본으로 그립니다("샘플 포토카드", 교환권 `XK4T-9P2M` 등).
**표본 이미지는 안 넣습니다** — 슬롯이 올린 카드가 있으면 그게 나오고, 없을 때 제가 남의
그림을 지어내지 않습니다.

주최자 화면은 목록에 없습니다(고정 라이트라 슬롯 색과 무관합니다). **스태프 화면은 있습니다** —
슬롯 색을 쓰고 손님이 같이 보는 화면이라 색을 고르는 자리에서 봐야 합니다.

### 1-5. 검증 스크립트 세 곳이 낡아 있어서 고쳤습니다 ✔

제 코드가 아니라 **검사 쪽이 옛 화면을 보고 있었습니다** (전부 이번 작업 이전부터):

  (이 검사는 살려둘 값어치가 있습니다: 색 고르개가 리렌더에 다시 만들어지면 **드래그로
  색을 못 고릅니다.**)
- `verify-pages` 는 `demo` 라는 타로 슬롯을 전제하는데 지금 DB 에 타로 슬롯이 없어
  터졌습니다 → 슬러그를 인자로 받고, 없으면 그렇게 말하고 멈춥니다.

### 3-2. Q1-b. 포토카드 이미지의 권리 — **결정이 필요합니다** (그대로)

| 스탬프 | 칸 개수·이름·도장 그림, 색·문구 | 현장 암호, 보상 방식, 자정 리셋, 마감 |
| 모의고사 | 칭호(이름·그림), 색·문구 | 문항·정답·커트라인·제한시간·정답 공개 |
| 포토카드 | 카드 이미지·이름, 색·문구, **박스·수량 고르기 모양** | **레어도·재고·럭키**, 운영 방식, 연습, 마감 |
| 포토존 | 프레임 PNG, 색·문구 | (없음 — 안내 한 장) |
| 소원나무·롤페 | 등불/쪽지 색·모양, 배경, 실루엣 여백 | 후검수 (숨기기·삭제) |
| 투표 | 색·문구·결과 표시 방식 | 설문·선택지·공개·마감 |

가른 기준은 하나입니다: **행사 중에 바뀌는 값이면 주최자, 배포 전에 정하는 값이면 편집기.**
예외가 하나 있는데 **이미지 업로드는 무조건 편집기**입니다 — Storage 쓰기가 담당자 계정으로만
잠겨 있고(방문자 사진 호스팅으로 번지지 않게) 그 잠금을 안 푸는 게 이 플랫폼의 설계입니다.

## 6. 알아두실 것

- **`scripts/db.mjs`** 로 마이그레이션을 적용합니다 (`--pending` 확인 → `--migrate` 적용)
- **테스트 슬롯**: `treetest`(소원나무)·`phototest`(포토존)·`rollingtest`(롤페)·`stamptest`·
  `quiztest`·`pctest`·`luckytest`. 편집기에서 지우시면 딸린 데이터까지 같이 지워집니다
- **화면 찍는 도구** (개발 서버 5174 가 떠 있어야 합니다)
  - `node scripts/shot.mjs /경로 out.png` — 로그인이 필요 없는 화면
  - `node scripts/shot-staff.mjs <slug> out.png [--draw 5]` — 스태프 화면(로그인 뒤에 있습니다).
    `--draw` 를 주면 실제로 뽑아 당첨·전체 결과까지 찍습니다 (**연습 모드에서 쓰세요**)
  - `node scripts/shot-preview.mjs <slug> 폴더` — 편집기 미리보기의 화면들을 차례로
  - `node scripts/pcmode.mjs <slug> save|gift|sale` — 포토카드 운영 방식 임시 변경 (검증용)
- **개발 서버(Vite)가 가끔 옛 화면을 보여줍니다.** 특히 **여러 파일이 같이 쓰는 CSS**
  (이번에 만든 `DrawStage.module.css`)를 고쳤을 때, 그걸 받아쓰는 화면이 **옛 사본을 그대로
  들고 있습니다** — 이번에도 "고쳤는데 화면이 그대로" 로 한 번 겪었습니다. 배포본에는 없는
  현상이니, 이상하면 개발 서버를 재시작하세요
