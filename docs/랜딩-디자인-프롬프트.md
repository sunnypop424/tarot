# 랜딩페이지 디자인 프롬프트 (Claude 디자인용)

아래 **"프롬프트" 블록을 통째로 복사해서** Claude 디자인에 넣으시면 됩니다.
마음에 든 레퍼런스(`랜딩 L v2.dc.html`)를 **같은 대화에 첨부**하고 "이 리듬을 따르라"고 지시하는 게
핵심이라, 프롬프트 첫 줄에 그 문장을 넣어 뒀습니다.

받아오시면 제가 `/` 라우트에 붙이겠습니다 (지금은 루트가 404 입니다 — 슬롯이 없는 주소라서요).
붙일 때 제가 지킬 것: **슬롯 목록은 절대 노출하지 않습니다.** 랜딩에 뜨는 건 아래 체험 주소뿐이고,
고객 이벤트 주소는 랜딩 어디에도 안 나옵니다.

**체험용 슬롯은 테스트 슬롯과 따로 만듭니다** (`/demo-*`). 지금 쓰는 `pctest`·`stamptest` 같은 건
제가 검증하며 데이터를 갈아엎는 자리라 랜딩에 걸면 안 됩니다. 체험 슬롯은
**샘플 데이터를 채우고 방문자 쓰기를 서버에서 막습니다** — 체험은 되지만 남는 건 없어요
(뽑아도 재고가 안 줄고, 남긴 쪽지는 그 폰에만 보입니다). 이미지는 사장님이 편집기에서 올리시면 됩니다.
**아래 프롬프트의 주소는 그 체험 슬롯 기준으로 이미 적어 뒀습니다.**

```
첨부한 `랜딩 L v2.dc.html` 의 **리듬·여백·타이포 대비·섹션 전환 감각을 그대로 따라서**,

"넓은 여백 → 큰 문장 → 조용한 증거" 로 이어지는 그 흐름은 유지해 주세요.

## 무엇을 파는 제품인가

**생일카페 이벤트 페이지를 '슬롯' 단위로 파는 플랫폼**입니다.
아이돌 팬이 여는 생일카페에서, 방문자가 QR 을 찍고 폰으로 여는 이벤트 페이지를
행사 단위로 빌려주는 서비스예요. 앱 설치가 없고, 주소 하나가 곧 그 행사입니다.

- 사는 사람: 생일카페를 여는 주최자 (대부분 개인 팬, 20대 여성, 처음 여는 사람도 많음)
- 쓰는 사람: 카페에 온 방문자 (전부 모바일, 대기 줄에서 30초 안에 끝나야 함)
- 파는 사람: 우리 (슬롯을 만들어 색·이미지·문구를 세팅해 넘긴다)

핵심 문장은 이것입니다: **"이벤트 하나에 페이지 하나. 준비는 우리가, 운영은 주최자가."**

## 실을 서비스 아홉 개 (전부 실제로 도는 것들)

각 카드에 이름 · 한 줄 설명 · "체험해보기" 링크가 들어가야 합니다.

1. **타로카드** — 궁금한 걸 고르면 카드를 뽑고 해석이 나온다 · /demo-tarot
2. **럭키드로우** — 스태프가 경품을 추첨한다. 등수·재고·스크래치 연출 · /demo-luckydraw
3. **롤링페이퍼** — 방문자가 응원 메시지를 남기고 벽에 붙는다 · /demo-rolling
4. **소원 나무** — 소원을 적어 등불로 매단다. 밤하늘 버전의 롤링페이퍼 · /demo-wish
5. **포토존 프레임** — 사진에 이벤트 프레임을 씌워 저장한다 · /demo-photozone
6. **실시간 투표** — 즉석 투표, 결과가 그 자리에서 차오른다 · /demo-poll
7. **방문 스탬프** — 현장 암호로 도장을 모으고 다 모으면 선물 교환 · /demo-stamp
8. **최애 모의고사** — 문제를 풀고 점수와 칭호를 받는다. 칭호 카드는 저장·공유 · /demo-quiz
9. **포토카드 뽑기** — 레어도 가챠. 저장용 / 1장 증정 / 판매 세 가지로 운영 · /demo-photocard

이 주소들은 **체험 전용 슬롯**입니다. 샘플 데이터가 들어 있고, 눌러 보는 건 되지만
서버에는 아무것도 안 남습니다 (그렇게 서버에서 막아 뒀습니다).

## 페이지에 반드시 있어야 할 것

1. **히어로** — 한 문장으로 무엇인지. 부제 한 줄. 행동 버튼 두 개
   ("서비스 둘러보기" / "문의하기"). 장식보다 여백으로 승부.
2. **서비스 아홉 개 그리드** — 카드마다 이름·한 줄·체험 링크.
   아홉 개가 한눈에 보이되 나열처럼 보이면 안 됩니다. 성격이 비슷한 것끼리
   (뽑기류 / 남기기류 / 모으기류) 묶어 보이면 좋습니다.
3. **체험 섹션** — 고른 서비스가 **폰 목업 안에서 실제로 뜨는** 구간.
   목업 안에 iframe 을 넣고, 왼쪽/위의 탭으로 서비스를 바꾸면 그 주소가 로드되는 구조로
   짜 주세요 (iframe src 는 위 체험 주소). 스크린샷 이미지가 아니라 **진짜 페이지**입니다.
   목업 아래에 "**체험용이라 눌러도 실제로 저장되지 않아요**" 한 줄과, 새 탭으로 크게 여는
   링크를 같이 두세요 (폰에서는 목업이 작아 직접 여는 게 낫습니다).
4. **어떻게 진행되나** — 3~4단계 (① 서비스 고르기 ② 색·이미지 세팅 ③ QR 인쇄 ④ 현장 운영).
   각 단계 한 줄씩. 과장 없이.
5. **주최자가 직접 하는 것 / 우리가 해주는 것** — 두 칸 대비.
   (우리: 페이지 제작·색·이미지·배포 / 주최자: 문항·경품·재고·현장 운영)
6. **자주 묻는 것** 4~6개 (앱 설치 필요한가요 / 기간이 끝나면 어떻게 되나요 /
   사진은 서버에 저장되나요 / 여러 서비스를 같이 쓸 수 있나요 /
   체험 페이지에서 남긴 건 어떻게 되나요).
7. **문의 CTA** — 트위터 DM 또는 폼 링크 자리. 실제 주소는 비워 두고 `#contact` 로.

## 비주얼 규칙

- **라이트 기본**, 다크 모드 대응(`prefers-color-scheme`).
- 색: 보라 계열 포인트 하나(#816BFF)와 무채색. 그라데이션은 히어로에만 아주 옅게.
- 모서리: 8px(카드) / 9999px(알약 버튼). 그림자는 아주 옅게 한 겹만.
- 폰트: Pretendard 계열 시스템 스택. 제목은 굵게(700~800), 본문 400.
- **모바일 우선.** 360px 에서 무너지지 않아야 하고, 1280px 에서 여백이 시원해야 합니다.
- 애니메이션은 스크롤 등장 정도만. `prefers-reduced-motion` 을 존중.

## 기술 제약 (중요)

- **파일 하나로**: HTML 하나에 `<style>`·`<script>` 인라인. 외부 CDN·폰트 파일·이미지 링크 금지
  (아이콘이 필요하면 인라인 SVG).
- 이미지는 넣지 마세요. 자리에는 **회색 박스 + 캡션**만 두면 제가 실제 이미지를 채웁니다.
- 체험 섹션의 iframe 은 `loading="lazy"`, 고정 비율(390×844) 목업 안에서 `transform: scale()` 로 축소.
- 클래스 이름은 의미 기준으로(`.hero`, `.services`, `.demo`), 유틸 남발 금지.
- 접근성: 대비 4.5:1 이상, 탭 이동 가능, 이미지·아이콘에 대체 텍스트.
```

## 받아오신 뒤

1. 파일을 `example/` 아래에 두시면 제가 `/` 라우트에 붙입니다.
2. 붙일 때 제가 손볼 것:
   - 색·모서리·그림자를 우리 토큰(`src/styles/tokens.css`)으로 갈아끼웁니다 (hex 는 토큰 밖에 안 둡니다).
   - 체험 iframe 이 **체험 슬롯**을 가리키게 하고, 슬롯이 없을 때의 폴백을 넣습니다.
   - 체험 슬롯 아홉 개를 만들어 샘플 데이터를 채웁니다 (쓰기는 서버에서 막습니다).
     **이미지만 사장님이 편집기에서 올려 주세요** — 업로드는 최고관리자 계정으로만 되게 잠겨 있습니다.
3. 랜딩은 **슬롯 밖 화면**이라 슬롯 테마 토큰의 영향을 받지 않습니다 — 편집기(`.owner`)와 같은 결로
   고정 라이트로 두는 게 맞습니다.
