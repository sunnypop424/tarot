# 신규 서비스 6종 — 방문자 화면 디자인 프롬프트

Claude(claude.ai)에 아래 `---` 사이 내용을 **통째로** 붙여넣으면 서비스 6개의 방문자 화면 시안이
**각각 별도 아티팩트로** 나옵니다. 하나씩만 뽑고 싶으면 **§공통 규칙 + 원하는 서비스 절 하나**만
잘라서 붙여넣으세요 (한 번에 하나가 대체로 품질이 좋습니다).

**이 프롬프트의 의도 (중요)**

- **레이아웃·구성·반응형·질감만** 뽑는 게 목적이다. 색·폰트·크기·radius 같은 **디자인 토큰은
  일부러 정하지 않는다** — 실제 값은 이벤트(슬롯)마다 런타임에 입히고, 주최자가 고른다.
- 그래서 시안은 **중립 플레이스홀더 색**으로만 그려지고, 평가 기준도 색이 아니라 배치·비례·반응형·질감이다.
- **여기 있는 건 전부 방문자(손님) 화면이다.** 주최자·스태프 관리 화면은 `.admin` 고정 라이트
  디자인이라 이 프롬프트의 대상이 아니다 (`DESIGN_PROMPT_EDITOR.md` 쪽).

**사용 팁**

- 한 번에 안 나오면 "등불을 더 겹치게", "덱을 더 넓게 부채꼴로", "결과 화면을 더 극적으로"
  같은 후속 요청으로 다듬으세요.
- 서비스마다 **못 살리면 실패인 것**을 한 줄로 못박아 뒀습니다. 시안이 밋밋하면 거기부터 보세요.

너는 모바일·데스크톱 웹 UI 디자이너다. 아이돌 **생일카페 이벤트 페이지**에 얹히는 서비스 6종의
**방문자 화면** 시안을 만들어라.

각 서비스마다 **별도 HTML 아티팩트 하나씩, 총 6개**를 만든다. 한 아티팩트에 여러 서비스를 섞지 마라.

## §공통 규칙 (6개 전부에 적용 — 매번 다시 읽어라)

### 산출물

- **단일 HTML 아티팩트.** 인라인 CSS만 쓰고 외부 리소스(CDN·웹폰트·이미지·스크립트)를 절대
  불러오지 마라 — 아티팩트에서 차단된다.
- 실제 동작 앱이 아니라 **정지 시안**이다. hover·간단한 CSS 애니메이션 정도만.
- 한 서비스의 화면이 여럿이면 **한 아티팩트 안에 위에서 아래로 나란히** 배치하고, 각 화면 위에
  작은 라벨을 붙여라 (예: "① 프레임 고르기 / 390px").
- 일러스트·사진은 넣지 마라. 이미지가 들어갈 자리는 **회색 플레이스홀더 박스**로.

### 색·폰트·크기 (여기서 정하지 마라)

- **브랜드 색·hex·폰트·글자 크기·radius 를 고정하지 마라.** 실제 토큰은 이벤트마다 갈아끼워진다.
- 특히 **폰트 · 글자색 · 배경색 · 테두리색 · 테두리 유무**는 주최자가 고르는 값이다.
  교체 가능한 플레이스홀더로 두고, **테두리가 없는 버전도 배경만으로 요소가 구분되게** 설계해라.
- 중립 플레이스홀더 색으로만 그려라. 비례·여백·리듬은 네 판단으로 자연스럽게.
- **아이콘은 Lucide 만** 쓰고 SVG 를 인라인으로 직접 그려 넣어라 (stroke-width 1.5~2).
  **이모지 사용 절대 금지.**

### 반응형 (명시적으로 다 보여줘라)

- 기본은 **모바일 390px**다 — 손님은 카페에서 자기 폰으로 QR 을 찍어 들어온다.
- 넓은 화면이 의미 있는 서비스는 **태블릿 834px · 데스크톱 1280px+** 도 같이 그려라
  (어느 서비스가 그런지는 각 절에 적어뒀다).
- **모바일 확대판처럼 보이면 실패다.** 넓어지면 열이 늘거나 배치가 재구성돼야 한다.

### 공통 구성 요소

- **관리자 진입**: 각 서비스 첫 화면 구석(아주 아래 등)에 **방문자 눈엔 잘 안 띄는 흐릿한
  "관리자" 링크**를 하나. 주최자만 찾아 누른다. 크거나 화려하면 안 된다.
- **로고 자리**: 헤더에 이벤트 로고가 들어갈 수 있다 (없으면 제목 텍스트만). 플레이스홀더로.
- **제목·안내 문구는 전부 주최자가 정하는 편집 가능한 값**이다. 고정 문구로 박지 말고
  플레이스홀더로 두되, **짧은 것과 긴 것 둘 다 안 깨지게** 해라.

### 보상 화면 2종 (서비스 ④⑤⑥ 이 공유한다 — 한 번만 잘 만들고 재사용해라)

일부 이벤트는 조건을 달성한 손님에게 무언가를 준다. 주최자가 셋 중 하나를 고른다:
**없음 / 확정 선물 / 응모**. 뒤 둘은 화면이 필요하다.

- **(가) 교환권 카드** — 확정 선물일 때. 달성 즉시 뜬다.
  - **화면의 주인공은 교환 코드**다 (예: `XK4T-9P2M`). 카페 카운터에서 스태프가 손님 폰을 보고
    자기 기기에 **손으로 입력**하는 값이라, **멀리서도 읽히게 아주 크고 또렷하게.**
    글자 사이가 붙어 보이면 안 된다.
  - 코드 아래에 무엇을 받는지 한 줄(플레이스홀더) + 선물 이미지 자리(선택).
  - **수령 완료 상태**도 같이 그려라 — 코드가 흐려지고 "수령 완료" 도장 같은 표시 + 받은 시각.
    한 번 쓴 코드라는 게 스태프 눈에 즉시 보여야 한다.
  - "이 기기에만 저장돼요" 같은 작은 주의 문구 자리.
- **(나) 응모 폼** — 응모일 때. 당첨자는 나중에 주최자가 따로 발표한다.
  - 입력: **닉네임(필수)** · **트위터 아이디** · 연락처 · 주소.
    **뒤 셋은 이벤트마다 켜고 끈다** — 닉네임만 있는 버전, 닉네임+트위터만 있는 버전,
    전부 있는 버전이 **모두 자연스러워야 한다.** (한두 칸만 남았을 때 폼이 휑해 보이면 안 된다.)
  - 개인정보 안내 문구가 들어갈 자리를 **반드시** 두어라 (수집 항목·보관 기간·파기 시점).
    작지만 읽히게.
  - 제출 후 "응모했어요" 완료 상태도 한 컷.

## ① 포토존 프레임

카페 포토존에서 사진을 찍고 **이벤트 프레임을 씌워 저장해 가는** 인증샷 서비스.
인생네컷과 같은 문화다.

**못 살리면 실패**: 카메라 프리뷰 위에 프레임이 얹힌 화면이 **진짜 카메라 앱처럼** 보이는 것.

**반응형**: 모바일 390px 만 제대로. (폰으로 찍는 서비스라 데스크톱은 부차적 — 업로드 경로만 성립하면 된다.)

화면 셋을 순서대로:

**① 프레임 고르기**
- 이벤트 로고 + 제목 + 한 줄 안내.
- **프레임 목록**: 가로 스크롤 썸네일 (각각 이름표 — "정면컷", "네컷" 등 플레이스홀더).
  프레임은 투명 PNG 라 썸네일에 **체커보드 배경**을 깔아 투명 영역이 보이게.
  **프레임마다 비율이 다르다** (세로 3:4, 정사각, 세로 긴 4컷 등) — 썸네일이 비율을 지키게.
- 큰 버튼 둘: **[바로 찍기]** (주) · **[사진 올리기]** (부).

**② 촬영 (카메라 프리뷰 + 프레임 오버레이)**
- 화면 대부분이 **카메라 프리뷰**(검은 플레이스홀더). 그 위에 **고른 프레임이 정확히 겹쳐** 있다.
- 하단에 **큰 원형 셔터 버튼**. 좌우에 **전/후면 전환**(`switch-camera`)과 **프레임 바꾸기**.
- 상단에 촬영 안내 한 줄(주최자가 정하는 플레이스홀더).
- **카메라를 못 쓸 때의 화면도 같이 그려라** — 권한 거부/미지원. 안내 한 줄 +
  **[사진 올리기]** 로 자연스럽게 넘어가는 대안. (막다른 골목처럼 보이면 안 된다.)

**③ 결과**
- 합성된 사진 한 장이 **화면 중앙에 크게**. 이 화면은 사진이 전부다 — 주변을 비워라.
- 버튼 셋: **[저장]**(주) · **[공유]** · **[다시 찍기]**.
- 저장이 브라우저에 막힐 수 있어 **"사진을 길게 눌러 저장하세요"** 안내가 뜨는 변형도 한 컷.

## ② 소원 나무

롤링페이퍼의 다른 비주얼. 쪽지 대신 **소원을 적은 등불**을 나무에 매단다.

**못 살리면 실패**: 밤 분위기와 **등불이 은은히 빛나는** 느낌. 카드 그리드로 보이면 완전히 실패다.

**반응형**: 모바일 390px · 태블릿 834px · 데스크톱 1280px+ **전부**.
(부스에 놓인 태블릿·PC 로 다 같이 구경하는 화면이라 **큰 화면에서 살아 있어야 한다.**)

화면 둘:

**① 나무 (소원이 쌓이는 곳)**
- 배경은 **밤하늘/나무** 이미지 자리(플레이스홀더). 그 위에 등불이 매달린다.
- **등불 한 개 = 소원 한 개.** 나뭇가지에서 **가는 줄로 늘어뜨린** 형태 — 줄 길이가 제각각이라
  높낮이가 다르고, 아주 느리게 흔들린다.
- 등불에는 **본문 한 줄~두 줄**과 **남긴 이름**이 들어간다. 길면 잘리되 답답하지 않게.
- 등불은 **몇 가지 색을 섞어** 쓰고, 일부는 **작은 장식**(매듭·술 등 플레이스홀더)이 달린다.
- 은은한 빛 번짐 정도는 좋다. **읽는 데 방해되면 안 된다.**
- 넓어지면 나무가 **넓게 퍼지고 등불 수가 늘어난다** (모바일 확대판 금지).
- **빈 상태**: 나무에 등불이 하나도 없고 "첫 소원을 걸어 보세요" 가 외롭게.
- 눈에 띄는 **[소원 걸기]** 버튼 (모바일 하단 고정 / 데스크톱 헤더나 우하단).

**② 소원 적기 (별도 페이지)**
- 나무의 북적임과 달리 **차분하고 집중되는** 화면. 상단에 **[돌아가기]**.
- 입력: 이름(선택) · **소원(여러 줄, 이 화면의 주인공)** · **등불 색 고르기**(스와치 몇 개) ·
  **장식 고르기**(썸네일 중 택1, 선택).
- **내 등불 미리보기**를 곁에. 고른 색과 글이 실제 등불 모양으로 보이면 즐겁다.
- 아래 **[걸기]** 버튼. 데스크톱에선 폼을 가운데 카드로 모아라.

## ③ 실시간 투표

"최애 포토 고르기", "최애 곡" 같은 즉석 투표. 결과가 **실시간으로 차오른다.**

**못 살리면 실패**: 투표한 뒤 결과 막대가 **차오르는 순간의 쾌감.**

**반응형**: 모바일 390px + **태블릿 가로 1194×834**(아래 전광판).

화면 넷:

**① 설문 목록** — 설문이 여러 개일 수 있다. 카드 목록 + 각각 참여 여부 표시("참여함").
마감된 설문은 흐리게.

**② 투표하기**
- 질문이 크게. 아래 **선택지**.
- **선택지는 두 모양이다 — 둘 다 그려라.**
  - **텍스트형**: 세로 목록. 고르면 명확히 선택된 티가 난다.
  - **이미지형**: 사진(플레이스홀더) 그리드 — 모바일 2열, 넓으면 3~4열. 포토 투표용.
- **하나만 고르는 설문**과 **여러 개 고르는 설문**(예: 최대 3개) 둘 다 성립해야 한다.
  여러 개일 땐 "3개까지 고를 수 있어요 (2/3)" 같은 남은 개수 표시.
- 하단에 **[투표하기]**.

**③ 결과 (라이브)**
- 선택지마다 **가로 막대가 차오르고** 퍼센트가 붙는다. **내가 고른 항목은 확실히 구분되게.**
- 1위는 눈에 띄게. **막대 대신 하트가 채워지는 변형**도 한 컷 그려라 (주최자가 고른다).
- **표 수를 숨기는 버전**도 성립해야 한다 (퍼센트/막대만, 숫자 없음).
- "지금 이 순간 갱신 중" 이라는 느낌의 작은 표시.
- **이미 투표한 상태로 다시 들어온 화면**도 한 컷.

**④ 전광판 (태블릿 가로 1194×834)**
- 부스에 세워두는 화면. **글자와 막대가 아주 크고**, 멀리서 읽힌다.
- 순위가 바뀌는 걸 보여주는 게 목적이라 **1~5위만** 큼직하게. 조작 버튼은 없다.

## ④ 포토카드 뽑기

랜덤 포토카드를 뽑는다. **운영 방식이 셋**이고 방문자가 보는 화면이 각각 다르다 — **셋 다 그려라.**

**못 살리면 실패**: 카드가 뒤집히며 나오는 **한 장의 순간**. 여기서 밋밋하면 서비스가 없다.

**반응형**: 모드 A·B 는 모바일 390px 중심. 모드 C 는 안내 한 장이라 모바일만.

**모드 A — 저장용 (손님이 자기 폰으로 뽑고 이미지를 가져간다)**
- **① 덱**: 카드 뒷면이 **부채꼴로 펼쳐져** 있다 (10~20장). 뒷면은 이벤트 이미지 자리.
  한 장을 고르는 화면이라 **"고르고 싶게"** 보여야 한다. 위에 안내 한 줄.
- **② 뽑는 중**: 고른 카드가 덱에서 **날아 나와 화면 가운데로** 온다. 아주 짧은 긴장.
- **③ 결과**: 카드가 **뒤집히며** 앞면이 드러난다. 포토카드는 **세로로 길다**(대략 55:85 —
  타로 카드보다 좁고 길다). 카드 이름 + **[저장]** + **[한 번 더]**(횟수가 남았으면).
- **④ 보관함**: 지금까지 뽑은 카드들이 격자로. 모바일 3열. 탭하면 크게 + 저장.
  아직 못 뽑은 자리는 **실루엣**으로 남겨 수집욕을 자극해라. "3 / 12 종" 같은 진행 표시.
  **"이 기기에만 저장돼요"** 안내 필수.

**모드 B — 1장 증정 (손님 폰에서 뽑기권을 만들고, 스태프가 뽑아 실물을 준다)**
- **① 뽑기권 받기**: 안내 + 큰 **[뽑기권 받기]** 버튼. 한 번만 받을 수 있다는 걸 미리 알려라.
- **② 뽑기권**: **화면의 주인공은 4~6자리 코드**(예: `K7QM`). 스태프가 자기 기기에 손으로
  입력하는 값이라 **아주 크고 또렷하게, 글자 사이를 벌려서.**
  아래에 "카운터에 보여주세요" 한 줄. **다시 받을 수 없다**는 주의.
- **③ 뽑힌 뒤**: 스태프가 뽑고 나면 이 화면이 결과로 바뀐다 — 뽑힌 카드가 크게 +
  "실물을 받아 가세요". 저장 버튼은 **있을 수도 없을 수도 있다**(주최자가 정한다) —
  버튼이 없는 버전도 허전하지 않게.
- 손님이 화면을 새로고침해 확인하는 흐름이라, **아직 안 뽑힌 대기 상태**를 한 컷 그려라.

**모드 C — 판매 (스태프 기기에서만 뽑는다)**
- 손님 폰엔 **뽑기 화면이 아예 없다.** 안내 한 장만: "카운터에서 뽑을 수 있어요" +
  이벤트 로고·제목. 막다른 에러 화면처럼 보이면 안 된다 — **안내로 읽혀야 한다.**

## ⑤ 최애 모의고사

최애에 대한 문제를 풀고 점수와 **칭호**를 받는다.

**못 살리면 실패**: 결과 화면의 **칭호 카드**. 이게 트위터에 올라가는 물건이다.

**반응형**: 모바일 390px 중심 + 데스크톱 1280px(문항을 가운데 카드로 모은다).

화면 다섯:

**① 시작** — 제목·안내·문항 수·제한시간(있으면). 큰 **[시작하기]**.

**② 문항 (한 화면에 한 문제)**
- 상단 **진행바 + "3 / 10"**, 제한시간이 있으면 남은 시간.
- 문제 텍스트. **사진 문제**도 있다 — 이미지 자리(플레이스홀더)가 들어간 변형을 같이.
- **객관식**(선택지 목록, 고르면 명확히)과 **주관식**(한 줄 입력) 둘 다 그려라.
- 하단 **[다음]**. 마지막 문항은 **[제출하기]**.

**③ 채점 중** — 아주 짧은 대기. 과하지 않게 한 컷.

**④ 결과 — 칭호 카드가 주인공**
- **칭호**("찐팬 인증" 같은 플레이스홀더)가 가장 크다. 점수는 그 아래 부차적으로.
- 칭호 카드는 **그대로 저장·공유되는 이미지**다 — 정사각에 가까운 카드 한 장으로, 이벤트
  로고와 칭호와 점수가 담긴 **완결된 그림**이어야 한다. 주변 UI 와 분리돼 보이게.
- **[저장]** · **[공유]** 버튼.
- 아래에 **틀린 문제 다시보기**(주최자가 끌 수 있다 — 없는 버전도 자연스럽게).

**⑤ 보상** — 점수가 기준을 넘으면 §공통 **(가) 교환권 카드**, 응모 이벤트면 **(나) 응모 폼**.
보상이 없는 이벤트면 이 화면 자체가 없다. **세 경우를 다 그려라.**

## ⑥ 방문 스탬프

카페에서 **현장 암호**를 입력해 도장을 찍고, 다 모으면 선물을 받거나 응모한다.

**못 살리면 실패**: 도장이 **쾅 찍히는** 손맛. 체크박스 목록처럼 보이면 실패다.

**반응형**: 모바일 390px 만 제대로. (현장에서 폰으로 찍는다.)

화면 넷:

**① 스탬프판**
- **칸이 격자로 놓인 판**. 칸 수는 이벤트마다 다르다 — **4칸·6칸·9칸이 다 자연스럽게**
  (칸이 적을 때 휑하지 않고, 많을 때 답답하지 않게).
- 찍힌 칸은 **도장 자국**처럼 (살짝 기울고, 잉크가 번진 듯). 빈 칸은 흐린 자리 표시 +
  칸 이름(플레이스홀더 — "1번 카페" 등).
- 진행 표시 "3 / 6". 아래 **[암호 입력]** 버튼.
- 두 가지 주의 문구가 **경우에 따라 다르게** 뜬다 — 둘 다 그려라:
  "이 기기에만 저장돼요" / "오늘의 판이에요 · 자정에 초기화돼요".

**② 암호 입력**
- **4자리 정도의 칸 나뉜 입력**(OTP 처럼). 큰 숫자·글자.
- "카페에 붙은 암호를 입력해 주세요" 안내.
- **틀렸을 때** 상태도 한 컷 — 흔들림 + "암호가 맞지 않아요". 남은 시도 안내가 붙는 변형도.

**③ 도장 찍히는 순간** — 판으로 돌아와 **새 칸에 도장이 쾅 찍히는** 한 컷. 이 서비스의 보상이다.

**④ 완성** — 판이 다 찼을 때. 축하 + §공통 **(가) 교환권 카드** 또는 **(나) 응모 폼**.
보상이 없는 이벤트면 축하 화면만. **세 경우를 다 그려라.**

## 마지막 체크 (6개 전부에 대해)

제출 전 스스로 확인해라:

- 서비스마다 **별도 아티팩트**로 나눴는가? 한 곳에 섞지 않았는가?
- 각 서비스의 **"못 살리면 실패"** 항목이 실제로 살아 있는가?
- 색·폰트·**테두리(있음/없음 포함)**를 하드코딩하지 않고 교체 가능한 플레이스홀더로 뒀는가?
  테두리 없는 버전도 성립하는가?
- 제목·안내가 **편집 가능한 플레이스홀더**인가? 긴 제목도 안 깨지는가?
- 넓은 화면이 필요한 서비스(②③)가 **모바일 확대판**이 아니라 재구성됐는가?
- **코드를 보여주는 화면**(교환권·뽑기권)의 글자가 **멀리서 손으로 옮겨 적을 만큼** 큰가?
- 응모 폼이 **입력칸 1개일 때도, 4개일 때도** 자연스러운가? 개인정보 안내 자리가 있는가?
- 조건부 화면(보상 없음/확정/응모, 저장 버튼 유무, 카메라 실패)을 **다 그렸는가?**
- 각 서비스 첫 화면에 **방문자 눈엔 안 띄는 관리자 진입**이 있는가?
- 이모지 없이 **인라인 Lucide SVG 아이콘**만 썼는가? 외부 리소스를 안 불러왔는가?
