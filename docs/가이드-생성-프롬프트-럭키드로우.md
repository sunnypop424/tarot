# 럭키드로우 실사용 가이드 PDF — 생성 프롬프트

> 이 파일은 **가이드를 만들라고 시킬 때 그대로 붙여넣는 프롬프트**다. 가이드 본문이 아니다.
> 아래 「프롬프트」 절 전체를 새 세션에 붙여넣으면 캡처 → 문서 → PDF 까지 한 번에 나온다.

## 프롬프트 (여기부터 복사)

럭키드로우 서비스의 **실사용 가이드 PDF** 를 만들어줘. 이 레포(`c:\Users\sunny\Desktop\tarot`)
안에서 작업하고, 캡처는 **체험 슬롯 `demo-luckydraw`** 로만 뜬다.

### 0. 지켜야 할 전제

- **실사용 슬롯은 절대 열지 않는다.** 지금 실제 행사가 돌고 있어서 캡처 한 장이 남의 상품 구성·
  당첨 결과·배송 명단을 노출한다. 캡처 대상은 `demo-luckydraw` 하나뿐이고, 화면에 실명·연락처·
  주소가 보이면 그 캡처는 버리고 데모 데이터를 고쳐서 다시 뜬다.
- 체험 슬롯은 **매시간 기준 상태로 되돌아간다.** 캡처 세션 중간에 초기화되면 앞뒤 화면의 재고
  숫자가 어긋난다 — 캡처는 한 번에 몰아서 하고, 시작 전 상품·수량이 보기 좋은 상태인지 확인한다
  (필요하면 `node scripts/seed-demo.mjs` 로 다시 깐다).
- **연습(리허설) 모드를 켠 채로 캡처한다.** 재고가 안 줄어서 몇 번을 다시 찍어도 화면이 같다.
- 코드를 고치는 작업이 아니다. 가이드를 만들다 화면 버그를 발견하면 **고치지 말고 메모**해서
  마지막 보고에 따로 적는다.

### 1. 먼저 화면을 직접 확인한다 (추측 금지)

개발 서버는 포트 5174 고정(`npm run dev`). 아래를 **실제로 열어보고** 현재 화면 구성·버튼 문구·
메뉴 이름을 확인한 다음에 문서를 쓴다. 이 레포는 화면이 자주 바뀌어서, 코드 주석이나 기존 문서에
적힌 이름이 지금 화면과 다를 수 있다.

- 방문자/부스 화면: `/demo-luckydraw` (럭키드로우 셸 — 탭바 없이 화면 하나)
- 주최자 화면: `/demo-luckydraw/admin` (체험 슬롯은 로그인 없이 열린다)
- 스태프 기기 화면: `/demo-luckydraw/staff` (관리 화면 밖의 부스 기기용)

라우트 정의는 `src/App.tsx`, `src/admin/AdminRoutes.tsx`, `src/admin/AdminLayout.tsx` 에 있다.
화면 코드는 `src/luckydraw/`, `src/admin/luckydraw/`, `src/staff/`.
배경 지식(운영 모델·수량 워크플로우·묶음 제한의 대가)은 `docs/LUCKYDRAW-REVIEW.md` §5·§6.

### 2. 가이드가 다룰 범위 — 두 덩어리

**A. 방문자 화면** (부스에서 실제로 보이는 화면)

1. 뽑기 화면 — 개수 선택, DRAW, 남은 수량 배지, 마감 상태
2. 당첨 결과 — 스크래치(하이라이트 등수)와 순차 공개
3. 전체 결과 요약 — 등수·상품별 묶음
4. 배송정보 입력 — 배송이 필요한 상품이 나왔을 때만

**B. 주최자 화면** (`/{slug}/admin`)

1. 상품과 수량 — **적는 숫자가 곧 지금 뽑을 수 있는 수량**, 오늘/누적 소진은 읽기 전용
2. 운영 설정 — 연습/실운영, 마감·다시 열기, 잠금, 결과 표시 방식, 묶음 제한
3. 배송 정보 — 목록·CSV 내려받기·전체 삭제
4. 스태프 화면 열기 — 부스 기기에 띄우는 주소

정확한 메뉴 이름과 순서는 1번에서 확인한 실제 화면을 따른다(위 목록은 내용 범위이지 제목이 아니다).

### 3. 반드시 들어가야 할 운영 함정

기능 나열이 아니라 **현장에서 사고가 나는 자리**를 짚는 문서다. 아래는 빠뜨리면 안 된다.

- **연습 → 실운영 전환.** 연습 중에는 아무리 뽑아도 재고가 안 준다. 행사 시작 전에 반드시 끄고,
  껐는지 화면 어디에서 확인하는지까지 적는다.
- **수량 칸의 의미.** '남은 수량' 에 적은 값이 그대로 지금 뽑을 수 있는 수량이 된다. 이튿날
  운영은 *어제 남은 수 + 오늘 물량* 을 사람이 더해서 적는 방식이다.
- **수량 편집은 뽑기를 멈춘 상태(마감 또는 잠금)에서.** 편집 중에 다른 기기가 뽑으면 그 소진분이
  덮인다.
- **묶음 제한의 대가.** 켜면 저순위가 덜 쏟아지는 대신 **비싼 상품이 이론보다 빨리 소진된다.**
  기본은 꺼짐이고, 켜는 건 선택이라는 걸 분명히 한다.
- **배송 정보는 사본이 없다.** 전체 삭제 전에 CSV 를 먼저 내려받는다. 행사 마감 뒤 접근 가능한
  기간과 자동 삭제 시점이 있으니(코드/문서에서 실제 값을 확인해 적을 것) 언제까지 꺼내야 하는지
  날짜로 말해준다.
- **여러 기기를 같이 쓸 때** 재고가 어떻게 공유되는지, 무엇이 즉시 저장이고 무엇이 '저장하기' 를
  눌러야 반영되는지.
- **테마·색·이미지는 주최자가 바꾸는 항목이 아니다** (역할 분리). "이건 저희에게 말씀해 주세요" 로
  안내한다.

### 4. 캡처 방법

기존 스크립트를 재사용하거나(`scripts/shot.mjs`, `scripts/shot-staff.mjs`, `scripts/shot-admin.mjs`)
필요하면 가이드 전용 캡처 스크립트를 하나 새로 쓴다(`scripts/shot-guide.mjs`). 규칙:

- 셀렉트는 CSS 모듈 클래스가 아니라 **`data-*` 속성**으로 한다(클래스명은 빌드마다 바뀐다).
- 기기 크기를 화면 성격에 맞춘다 — 방문자·배송폼은 폰(390×844), **부스/스태프 화면은 아이패드
  가로(1180×820)**, 주최자 관리 화면은 데스크톱 폭(1280 이상). 폰 폭으로 관리 화면을 찍으면
  실제 사용 모습과 다르다.
- `deviceScaleFactor: 2` 로 찍어야 PDF 에서 글자가 뭉개지지 않는다.
- 결과·스크래치처럼 **연출이 끝난 뒤** 찍어야 하는 화면은 충분히 기다린다(스크래치는 덮인 상태와
  긁은 상태 **둘 다** 필요하다).
- 캡처 파일은 `docs/guide/luckydraw/` 아래 `01-draw.png` 처럼 순서가 보이는 이름으로 저장한다.
- 한 장씩 **직접 열어보고** 빈 화면·잘린 요소·에러 토스트가 없는지 확인한다. 빌드가 통과했다는
  것과 화면이 제대로 찍혔다는 것은 다른 얘기다.

### 5. PDF 만드는 법

레포에 `puppeteer-core` 가 이미 있다. **HTML 한 장을 쓰고 `page.pdf()` 로 A4 PDF 를 뽑는다**
(새 의존성 추가 금지).

- 출력: `docs/guide/럭키드로우-사용안내.pdf`, 원본 HTML 은 같은 폴더에 남긴다.
- A4 세로, `printBackground: true`, 여백 15~20mm.
- **외부 폰트·CDN 을 쓰지 않는다.** 시스템 한글 폰트(맑은 고딕 등)로 지정하고, 이미지는
  `file://` 경로나 data URI 로 넣는다. 오프라인에서 열어도 똑같이 보여야 한다.
- 캡처는 본문 폭에 맞춰 넣고 **캡션(무엇을 하는 화면인지)** 을 붙인다. 화면 안의 특정 버튼을
  가리켜야 하면 캡처 위에 번호 뱃지를 얹고 본문에서 그 번호를 부른다.
- 화면 캡처가 페이지 사이에서 잘리지 않게 한다(`break-inside: avoid`).
- 표지 + 목차를 넣고, 각 절은 새 페이지에서 시작한다.

### 6. 문체

- 한국어 **합니다체**, 상대는 IT 담당자가 아니라 **카페 현장의 주최자**다.
- 톤 기준은 `docs/고객-안내-템플릿.md` — "설정은 저희가 해뒀고, 당신은 이것만 하시면 됩니다".
- 사람은 **방문자 / 주최자 / 스태프** 세 단어로만 부른다. 개발 용어(슬롯·슬러그·RPC·RLS)는
  본문에 쓰지 않는다.
- 화면에 실제로 쓰여 있는 버튼 문구를 그대로 인용한다(내가 지어낸 이름을 쓰지 않는다).

### 7. 끝내고 보고할 것

- 만든 파일 목록(캡처 몇 장, HTML, PDF)과 PDF 페이지 수
- PDF 를 실제로 열어 확인했는지 — 한글이 깨지지 않았는지, 이미지가 다 보이는지
- 캡처에 개인정보가 없다는 확인
- 가이드를 쓰다 발견한 화면 버그·문구 오류(고치지는 말고 목록만)
- 확인 못 해서 추측으로 적은 부분이 있으면 그 자리를 명시

## 참고 — 왜 이렇게 시켰나

| 지시 | 이유 |
|---|---|
| 데모 슬롯만 캡처 | 실사용 중이라 캡처 한 장이 남의 행사 데이터다 |
| 연습 모드 ON | 재고가 안 줄어 캡처를 몇 번이든 다시 뜰 수 있다 |
| 화면을 먼저 열어보게 함 | 문서·주석의 화면 이름이 현재 화면과 어긋나 있는 경우가 있다 |
| `data-*` 셀렉트 | CSS 모듈 클래스명은 빌드마다 바뀐다 |
| 아이패드 가로 | 부스 기기가 가로다 — 폰 폭으로 찍으면 실제와 다른 배치가 나온다 |
| 외부 폰트·CDN 금지 | 오프라인/인쇄 상황에서 글자가 깨진다 |
| 운영 함정 목록 고정 | 기능 설명은 화면을 보면 알지만, 사고는 늘 이 자리에서 난다 |
